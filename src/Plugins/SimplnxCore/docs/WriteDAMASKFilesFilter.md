# Write DAMASK Files

## Group (Subgroup)

IO (Output)

## Description

DAMASK is a simulation package for crystal plasticity and other continuum mechanical models. This filter writes two DAMASK input files from an **Image Geometry**:

- `<name>.geom` contains the regular grid, physical size, origin, homogenization index, microstructure count, and spatial microstructure IDs.
- `material.config` contains texture orientations and microstructure constituents.

This pair of files is the DAMASK 2.x input format. DAMASK 3 uses a `.vti` geometry file plus YAML configuration files.

The geometry header writes `grid` in cell counts. It writes `size` and `origin` in the length units of the selected **Image Geometry**. The physical size is the cell count multiplied by the cell spacing for each axis.

The filter writes microstructure IDs in x-fastest order with `dims[0]` values on each line.

The filter supports two data formats. Pointwise output treats each **Cell** as a separate microstructure and assigns IDs from *1* through the number of cells. Grainwise output uses the selected feature ID of each cell and writes one microstructure for each ID from *1* through the maximum positive feature ID.

The compression option applies only to pointwise output. It writes the point IDs as one `1 to N` range instead of a grid of individual IDs.

### Required Input Sources

- **Image Geometry** defines the grid, spacing, origin, and number of cells.
- **Feature Ids** is an `int32` scalar array. Grainwise output uses each value as the cell microstructure ID.
- **Cell Euler Angles** is a `float32` array with three components. Input angles are in radians. The filter writes angles in degrees.
- **Cell Phases** is an `int32` scalar array. The filter writes each value as the constituent phase ID.

The three selected arrays must have one tuple for each cell in the **Image Geometry**.

### Material Configuration Completion

The generated `material.config` file contains the `<texture>` and `<microstructure>` sections. Add suitable `<homogenization>`, `<crystallite>`, and `<phase>` sections before using the file in a complete DAMASK simulation.

### Grainwise Behavior

The filter reads cells in linear index order. If multiple cells have the same positive feature ID, the last cell supplies the phase and Euler angles for that grain.

Euler angles are converted with double precision; the legacy filter rounded grainwise angles to single precision before writing.

Feature ID *0* and negative feature IDs do not supply grain phase or orientation data. These raw values remain in the geometry grid.

The filter writes every grain ID from *1* through the maximum positive feature ID. If an ID in this range has no cells, the filter writes phase *0* and zero Euler angles for that grain. The filter sends one warning that reports the number of missing grains.

If grainwise input has no positive feature IDs, the filter returns an error and does not write either output file.

The output directory must exist before execution. The legacy DREAM.3D 6.6 filter created the directory when it did not exist.

The Homogenization Index must be *1* or greater because DAMASK numbers homogenization entries from *1*.

### Memory

Pointwise output does not allocate temporary arrays. Grainwise output uses direct-indexed phase and orientation arrays proportional to the maximum positive feature ID. It does not allocate per-cell temporary storage.

## Example Output

This example uses a `3 x 2 x 1` **Image Geometry** with spacing `(0.5, 0.25, 2.0)` and origin `(1, -1, 0.5)`. The pointwise output is not compressed. The homogenization index is *2*.

`damask_test.geom`:

```text
6       header
# Generated by DREAM.3D
grid    a 3    b 2    c 1
size    x 1.500    y 0.500    z 2.000
origin    x 1.000    y -1.000    z 0.500
homogenization  2
microstructures 6
         1          2          3
         4          5          6
```

`material.config`:

Each `(gauss)` line in the generated file ends with one ASCII space. The code block omits that invisible character so repository whitespace checks remain valid.

```text
#############################################################################
# Generated by DREAM.3D
#############################################################################
# Add <homogenization>, <crystallite>, and <phase> for a complete definition
#############################################################################
<texture>
[point1]
(gauss) phi1 0.000   Phi 0.000    phi2 0.000   scatter 0.0   fraction 1.0
[point2]
(gauss) phi1 15.000   Phi 22.500    phi2 30.000   scatter 0.0   fraction 1.0
[point3]
(gauss) phi1 30.000   Phi 45.000    phi2 60.000   scatter 0.0   fraction 1.0
[point4]
(gauss) phi1 45.000   Phi 67.500    phi2 90.000   scatter 0.0   fraction 1.0
[point5]
(gauss) phi1 60.000   Phi 90.000    phi2 120.000   scatter 0.0   fraction 1.0
[point6]
(gauss) phi1 75.000   Phi 112.500    phi2 150.000   scatter 0.0   fraction 1.0
<microstructure>
[point1]
crystallite 1
(constituent)   phase 1 texture 1 fraction 1.0

[point6]
crystallite 1
(constituent)   phase 2 texture 6 fraction 1.0
```
