## How it was generated

The archived `identify_sample_v2/Generate_Exemplars.py` creates a 16×14×12 image from hand-designed text masks in `identify_sample_v2/generated_data/`. It reads each input into both `DataContainer/CellData/Mask` and `DataContainer/CellData/Mask Exemplar`. It runs `IdentifySampleFilter` on `Mask Exemplar`, then writes both arrays with `WriteDREAM3DFilter`. The script generates twelve files named `{whole,sliced}_{xy,xz,yz}_{nofill,fill}.dream3d`.

The source mask layout is documented in `identify_sample_v2/generated_data/ReadMe.md`. Coordinates are inclusive. The main-sample extent has 800 cells before the hole is removed.

| Feature | X range | Y range | Z range | Cells | Purpose |
|---|---|---|---|---|---|
| Main sample extent | 3–12 | 2–11 | 2–9 | 800 | Largest component. |
| Hole | 6–9 | 5–8 | 4–7 | 64 | Enclosed false region. |
| Internal island | 7–8 | 6–7 | 5–6 | 8 | True island within the hole; checks the visited-flag reset. |
| Noise A | 0–1 | 6–7 | 5–6 | 8 | Disconnected component in XY and XZ slices. |
| Noise B | 7–8 | 0–1 | 0–1 | 8 | Disconnected component in YZ slices. |
| Noise C | 14–15 | 9–10 | 8–9 | 8 | Disconnected component in XY and XZ slices. |

The twelve parameter combinations represent eight distinct behaviors: two whole-image fill settings and six slice settings. The plane parameter does not change whole-image execution. The top-level ReadMe's description of a 25×25×25 cylinder volume conflicts with the generation script and the feature-layout ReadMe; it does not describe these fixtures.

## Canonical oracle output

The archive provides regression expectations generated by the filter under test. Its outputs are circular references, not an independent correctness oracle. The independent Class 1 expectations are encoded in C++.

| DataPath | Source of expected values |
|---|---|
| `DataContainer/CellData/Mask Exemplar` | Archived SIMPLNX output, compared with the filtered `DataContainer/CellData/Mask`. |
| `Image/CellData/Mask` in the three non-square cases | Class 1: only indices 0, 1, 3, and 4 remain true. |
| `Image/CellData/Mask` in the hidden HDF5 case | Class 1: geometric membership predicate for the connected region, with the center hole controlled by `FillHoles`. |

The non-square input is:

```text
T T F
T T F
F F T
F F T
```

The four-cell component uses indices 0, 1, 3, and 4. The two-cell component uses indices 8 and 11. The expected mask is:

```text
T T F
T T F
F F F
F F F
```

The same linear arrays are embedded in images of size `{3,4,1}`, `{3,1,4}`, and `{1,3,4}`. Each case asserts all twelve values with whole-image processing and hole filling disabled. These fixtures test connectivity and row stride; they do not test the flat-image hole-fill difference.

The hidden `genuine HDF5 equivalence-page and slice oracle` builds a 129×129×3 image. Its first slice has more than 8000 isolated labels. The next slice joins the cells at `x < 127`, while cells at `x == 128` remain disconnected. A bridge above the interior hole keeps the upper voxel connected to the main component. The expected predicate retains `x < 127` with the checkerboard condition on slice zero; the hole at `(10,10,1)` becomes true only with hole filling enabled. The fixture checks all 49,923 output values for each fill setting and checks the CCL dispatch counter.

The five ordinary cases use resident mask stores. The scenario harness selects BFS and CCL; the default `SIMPLNX_TEST_ALGORITHM_PATH` is 0 (both). All pass in CI at `419f9db35` on Linux, macOS, and Windows in in-core builds. The algorithm and test sources match that commit.

Source inspection establishes the following release exposure. Each row was checked with `git show upstream/release/v<version>:<path>`, not inferred from release dates.

| DREAM3D-NX releases | Inspected source | Boundary and slice behavior |
|---|---|---|
| v7.0.0 through v7.0.1 | `src/Plugins/SimplnxCore/src/SimplnxCore/Filters/IdentifySampleFilter.cpp` | Whole-image coordinate boundary test; single false voxel stays false; no slice mode. |
| v7.0.2 through v7.4.0 | Same filter source path | Same whole-image boundary test; slice ties use `>`; slice fill uses the wrong global index and omits the visited reset. |
| v7.4.1 | `src/Plugins/SimplnxCore/src/SimplnxCore/Filters/Algorithms/IdentifySample.cpp` | Same whole-image boundary test; slice ties still use `>`; slice index and visited reset are corrected. |
| v7.4.2 | Same algorithm source path | Dimensional BFS with the single-voxel boundary guard; slice ties use `>=`; slice index and visited reset remain corrected. |

`IdentifySample-D1` predates the V&V report. PR #1590 (`e76ad508e`) replaces whole-image coordinate boundary checks with dimensional neighbor checks. That change also creates the single-voxel defect, `IdentifySampleFilter-D2`, between releases. PR #1640 (`a332e7369`) corrects D2 and the slice tie rule (`IdentifySampleFilter-D3`). PR #1562 (`42bc9ba6e`) corrects the slice write index and visited reset (`IdentifySampleFilter-D4` and `IdentifySampleFilter-D5`).

DREAM.3D tag `v6.5.171`, `Source/Plugins/Processing/ProcessingFilters/IdentifySample.cpp`, uses the coordinate boundary test, resets `checked` before hole filling, and selects a later component on a tie with `>=`. It has no slice mode. This source confirms D1, excludes the legacy application from D2–D5, and explains why the older visited-reset defect was specific to SIMPLNX slice processing.

PR #1568 (`4ec21e93f`) introduces CCL after the latest listed release. Current `IdentifySampleCCL.cpp` uses all three coordinate extrema to mark boundary roots. For a flat image, this condition marks every false component as exterior. Current `IdentifySampleBFS.cpp` ignores the flat axis, so a 5×5×1 true mask with a false center has different hole-fill behavior between the algorithms (`IdentifySampleFilter-D6`). The existing flat-image tests disable hole filling. This finding is from source inspection, not a new execution.
