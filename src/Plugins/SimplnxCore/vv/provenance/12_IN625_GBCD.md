## How it was generated

The archive contains `12_IN625_GBCD.dream3d`, `.vtk`, and `.xdmf` files. The embedded `/Pipeline/Pipeline` in the `.dream3d` file records a local proof version importing `01_IN625_RawEBSD.h5ebsd`, reconstructing features, creating and smoothing a triangle mesh, and extracting internal surfaces. Step 30 runs `FindTriangleGeomCentroids` on `TriangleDataContainer/FaceData/FaceLabels` and writes `FaceFeatureData/Centroids`; step 34 writes the data file. The source input is EBSD data, not a hand-constructed analytical fixture.

The archived face-label array has 1,874,216 tuples and two components. Its first component includes -1; all second-component labels are positive. The maximum label is 819, and the centroid array has 820 tuples with three components, so the exemplar does not exercise feature-matrix growth.

Each feature uses a distinct set of vertex indices; shared triangle vertices count once. Distinct vertices at the same position still count separately.

The geometry bounds are X = [0,4], Y = [1,3], and Z = [0,0]. Only X can touch both opposing faces in this fixture. For F3, unwrap the seam coordinates to `{4,3,3.5,4}`; their mean is 3.625. F4 has tied largest gaps and uses the arithmetic mean. Each mode checks all 15 centroid components within absolute tolerance `1e-4`, all populated-feature bounds, and tuple dimensions.

All pass in CI at `419f9db35` on Linux, macOS, and Windows. The current test, algorithm, and `GeometryHelpers.cpp` match that source snapshot.
