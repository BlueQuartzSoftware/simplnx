## Inline test fixtures

All oracle assertions are embedded directly in `test/ComputeFeaturePhasesFilterTest.cpp`. No archived outputs are used.

**Derivation methodology:** `featurePhases[f]` equals the phase of the last cell (ascending index) belonging to feature `f`. For consistent datasets the result is unambiguous. `featurePhases[0]` is always `0` (zero-initialized by `CreateArrayAction`; never written — deviation D1).

| Fixture | TEST_CASE suffix | Purpose | Paths |
|---|---|---|---|
| A | `Valid: Uniform Phases` | 7 cells, 3 features, no conflict; normal accumulation, no warning | 6, 7, 10 |
| B | `Valid: Feature 0 Skip` | 6 cells, 2 features + background; `featurePhases[0]` stays 0 (D1) | 4, 10 |
| C | `Valid: Mixed Phase Warning` | 2 cells, 1 feature, phase conflict; warning code -500 | 8, 9 |
| D | `Valid: Truncated Mixed Feature Warning` | 16 conflicting features; truncation suffix "and 1 more occurrence" | 9 (truncation) |
| E | `Invalid: FeatureId Out Of Bounds` | featureId 5 with Feature AM of 3 tuples; error -5351 | 1 (partial — OOB only) |
| F | `Invalid: Cell Array Size Mismatch` | featureIds (4 tuples) vs cellPhases (5 tuples); error -61860 | 2 |
| G | `Invalid: Negative Cell Phase` | cellPhases contains -1; error -61861 | 5 |

**Known gap:** Negative featureId (-5355 path) not tested — only OOB (-5351) is covered by Fixture E.
