## How it was generated

PR #1124 first registered this archive while updating the Small IN100 test data for a voxel-center correction in ComputeShapes. The former feature-phase test loaded `6_6_stats_test_v2.dream3d` and compared computed phases with the stored `DataContainer/Cell Feature Data/Phases` array. PR #1672 (`bbc470e6d`) replaced that test with ten hand-built fixtures in `src/Plugins/SimplnxCore/test/ComputeFeaturePhasesFilterTest.cpp`. Those fixtures create their cell and feature arrays directly in C++.

The comparison inputs and expectations are separate artifacts: `vv_work:ComputeFeaturePhasesFilter/generate_inputs.py`, `vv_work:ComputeFeaturePhasesFilter/compare_outputs.py`, and the six `pipeline_simpl_<A|B|C>.json` and `pipeline_nx_<A|B|C>.d3dpipeline` files. `vv_work:ComputeFeaturePhasesFilter/run_ab_test.sh` names a stock DREAM.3D v6.5.171 runner, but invokes only Cases A and B. The folder contains no ReadMe or result files. The reported comparison date is 2026-07-10; subsequent algorithm changes are `bbc470e6d` (2026-08-12, PR #1672: validation and background handling) and `4ec21e93f` (2026-09-20, PR #1568: chunked reads and cached output).

## Canonical oracle output

The current oracle is in the test source. No archived phase array supplies its expected values. For each positive feature, select the last cell in input order; its phase is the expected feature phase. Feature zero and unused features have value zero.

| DataPath | Source of expected values |
|---|---|
| `FeatureData/Phases` in `Valid: Uniform Phases` | Class 1: IDs `[1,1,2,2,2,3,3]` and phases `[1,1,2,2,2,1,1]` give `[0,1,2,1]`. |
| `FeatureData/Phases` in `Valid: Feature 0 Skip` | Class 1: IDs `[0,0,1,1,2,2]` and phases `[2,2,1,1,2,2]` give `[0,1,2]`. |
| `FeatureData/Phases[1]` in `Valid: Mixed Phase Warning` | Class 1: phases `[1,2]` on feature 1 give final phase 2 and one conflicting feature. |
| `FeatureData/Phases` in `Valid: Gap Feature Stays Zero` | Class 1: features 1 and 3 have phases 1 and 2; all five output values are `[0,1,0,2,0]`. |
| `FeatureData/Phases` in `Valid: Negative Cell Phase On Background Cell` | Class 1: IDs `[0,1,1]` and phases `[-5,2,2]` give `[0,2]`. |

The remaining fixtures check warning truncation and errors `-5351`, `-61860`, `-61861` and `-5355`. The truncation fixture checks the first 15 IDs and `and 1 more`; it does not compare output phases. Shape checks and absence of warnings on uniform positive features provide Class 4 checks. All pass in CI at `419f9db35` on Linux, macOS and Windows in-core builds.
