## How it was generated

The Small IN100 regression test loads `6_6_stats_test_v2.dream3d` from the archive. It compares the generated `Volumes`, `EquivalentDiameters`, and `NumElements` arrays with the archived arrays. These archived arrays supply regression expectations; the independent Class 1 expectations come from the inline fixtures below.

The three builders create synthetic geometries and hand-specified FeatureIds on each test invocation. Their Image inputs have zero origin and equal cell counts along the non-flat axes, but different axis spacings and feature counts. `CreateFeatureOutputDataStructure()` adds three output-block variants, including background and unused features. Its Image 2D expectations use the current slab formula.

| DataPath | Source of expected values |
|---|---|

| `Image/FeatureData/Volumes` | Class 1 cell count times cell area or volume, or sum of RectGrid cell volumes |
| `Image/FeatureData/EquivalentDiameters` | Class 1 circle or sphere formula applied to the feature area or volume |

The decimal derivations below explain the expected values. `Validate2DImageDataStructure()`, `Validate3DImageDataStructure()`, and `ValidateRectGridDataStructure()` contain the executable float32 expectations with relative tolerance `1e-6`. The flat-spacing case retains `[!shouldfail]`: it expects area 24 for flat X, Y, and Z, while the filter calculates 120 (`ComputeFeatureSizes-D3`).

**Source comparison and release evidence**

The legacy source is `Source/Plugins/Statistics/StatisticsFilters/FindSizes.cpp` at the DREAM.3D `v6.5.171` tag. `findSizesUnstructured()` accumulates float32 cell sizes into float32 feature volumes (D1). The diameter calculation reads the stored float32 size and uses `powf` or `sqrtf` (D2). The 2D Image calculation excludes the flat-axis spacing, and both geometry paths use serial loops. DREAM.3D v6.5.171 was not affected by D3, D4, or D5.

The current sources are `src/Plugins/SimplnxCore/src/SimplnxCore/Filters/Algorithms/ComputeFeatureSizesDirect.cpp` and `ComputeFeatureSizesScanline.cpp` in the same directory. Both use float64 compensated RectGrid sums and unrounded feature sizes for the diameter. Direct uses thread-local sums; Scanline keeps one compensation value per feature across input chunks.

Each fetched release branch was inspected with `git show upstream/release/v<version>:<path>`. Paths below are relative to `src/Plugins/SimplnxCore/src/SimplnxCore/Filters/`.

| Released versions | Source path | D3: flat spacing | D4: parallel reduction | D5: parallel scheduling |
|---|---|---|---|---|
| DREAM3D-NX v7.0.0 through v7.4.0 | `ComputeFeatureSizesFilter.cpp` | Excluded | Serial loops; defect absent | Serial loops; defect absent |
| DREAM3D-NX v7.4.1 | `Algorithms/ComputeFeatureSizes.cpp` | Excluded | Serial compensated sum; defect absent | Serial loops; defect absent |
| DREAM3D-NX v7.4.2 | `Algorithms/ComputeFeatureSizes.cpp` | Included; defect present | Compensation subtracted from incoming partial sum; fixed | Both FeatureIds residency guards present; fixed |

PR #1590 (`e76ad508e`) introduced D3. PR #1592 (`aaad2c4e2`) introduced the parallel code with D4 and D5. PR #1638 (`8d0b0ed22`) corrected the reduction and added both `requireStoresInMemory()` calls. DREAM3D-NX v7.4.2 contains both fixes. No release from DREAM3D-NX v7.0.0 through v7.4.2 contains D4 or D5. D3 remains in the current Direct and Scanline implementations.
