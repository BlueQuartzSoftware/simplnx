## How it was generated

The archive contains nine synthetic fixture pairs: Tests 01–07, 11 and 13. Their `test_NN_description.txt` files derive the expected FeatureIds and Phases from the selected component sizes and neighbor votes. `generate_dream3d_files.py` reads the input and expected text arrays, creates the geometry and arrays, and writes each file; it does not execute `FillBadDataFilter`. The Small IN100 pair, `6_5_input.dream3d` and `6_5_exemplar.dream3d`, supplies a separate regression comparison.

The manual comparison record, `vv_work:FillBadDataFilter/comparison_report.md`, is dated 2026-07-03. It records one 7×7×3 case at threshold 10 with Store Defects as New Phase off. It reports exact agreement of all 147 FeatureIds between the runner identified as DREAM.3D v6.5.171, a local proof version, SIMPLNX and the analytical array. The one-cell region becomes FeatureId 2; the 14-cell region stays zero. Output counts are 14 zeros, 124 ones and 9 twos.

`vv_work:FillBadDataFilter/create_test08_legacy.py` constructs the shared input. `vv_work:FillBadDataFilter/compare_outputs.py` contains the literal expected array and element-wise comparison. The preserved pipelines are `vv_work:FillBadDataFilter/fill_bad_data_6_5.json` and `vv_work:FillBadDataFilter/fill_bad_data_nx.d3dpipeline`. This comparison predates changes to the algorithm and does not verify current output parity.

The algorithm files changed after the comparison in `a9d7e17e3` (2026-07-14, V&V fixes), `4ec21e93f` (2026-09-20, BFS/CCL storage rewrite), `a33c370ca` (2026-09-25, messaging API) and `62000012e` (2026-10-20, progress reporting). These entries come from `git log --since=2026-07-03` on the current algorithm files.
