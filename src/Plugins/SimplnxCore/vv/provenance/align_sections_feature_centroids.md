## How it was generated

The `6_6_align_sections_feature_centroids.dream3d` member carries its generating pipeline in the HDF5
`Pipeline/Pipeline` dataset — an eleven-filter **DREAM3D 6.6** pipeline (`PipelineBuilder.Version 6`).
It reads the Small IN100 H5EBSD scan, thresholds it to a `Mask`, converts orientations, runs
`AlignSectionsMisorientation`, writes an intermediate file, runs `IdentifySample`, copies
`DataContainer` to `Exemplar Data`, and then runs `AlignSectionsFeatureCentroid` on the copy:

| Embedded filter 08 field | Value |
|---|---|
| `Filter_Name` | `AlignSectionsFeatureCentroid` |
| `Filter_Uuid` | `{886f8b46-51b6-5682-a289-6febd10b7ef0}` |
| `FilterVersion` | **6.6.331** |
| `GoodVoxelsArrayPath` | `Exemplar Data / CellData / Mask` |
| `UseReferenceSlice` | `1` |
| `ReferenceSlice` | `0` |
| `WriteAlignmentShifts` | `1` |
| `AlignmentShiftFileName` | `.../6_6_align_sections_feature_centroids/6_6_align_sections_feature_centroids.txt` |

So the `DataContainer` container in the file is the **unaligned** input and the `Exemplar Data`
container is the output of **legacy DREAM3D 6.6.331**, not of SIMPLNX. The archive's
`6_6_align_sections_feature_centroids.txt` is that same run's alignment shift file. A dump of the
embedded pipeline is kept with the V&V evidence at
`ww_work/AlignSectionsFeatureCentroid/archive_check/embedded_pipeline.json`.

Geometry: Image Geometry `189 x 201 x 60`, spacing `0.25 µm`, `Mask` stored as `uint8`.

## Oracle provenance

### Class 2 — reference implementation

* **Implementation:** DREAM3D 6.6.331, `AlignSectionsFeatureCentroid` filter, Reconstruction plugin.
* **Exact version:** 6.6.331, read from the `FilterVersion` field of the embedded pipeline's filter 08.
* **Runtime:** N/A — the reference is a compiled DREAM3D 6.6 binary, not a scripted environment. The specific build and host are not recoverable from the archive.
* **Random seed:** N/A — the algorithm is deterministic and takes no seed.
* **Script in archive:** N/A — the reference output is the archive's own `Exemplar Data` container and `6_6_align_sections_feature_centroids.txt`. The comparison script is not in the archive; it lives with the V&V evidence at `ww_work/AlignSectionsFeatureCentroid/scripts/archive_check.py`.
* **Output hash for drift detection:** the archive SHA512 above covers both reference artifacts.
* **Reference-slice mapping:** the archive was produced when `ReferenceSlice` indexed the filter's
  internal top-down iteration order, so `ReferenceSlice = 0` meant the section farthest from the Z
  origin. `ReferenceSlice` is now a physical slice index (see
  `vv/deviations/AlignSectionsFeatureCentroidFilter.md` entry `-D1`), so the equivalent request is
  `ReferenceSlice = zDim-1 = 59`. The `Algorithm Test` case reads the Z dimension from the geometry
  and passes `zDim-1`, with an in-test comment recording the mapping.
* **Independent verification performed 2026-08-21:** running post-fix SIMPLNX on this archive's
  unaligned `DataContainer` with `ReferenceSlice = 59` and *Store Alignment Shifts* enabled
  reproduces the 6.6.331 shift file on all 59 rows: the slice-pair and cumulative X/Y shift columns
  are exactly equal, and the centroid columns agree within the text file's six-significant-digit
  precision (`atol = 6e-4`, `rtol = 0`). The "New X/Y Shift" columns are excluded from the comparison
  because DREAM3D never assigns them (see deviation `-D3`), so they are constant `0` in every legacy
  row. Script: `ww_work/AlignSectionsFeatureCentroid/scripts/archive_check.py`; captured run:
  `ww_work/AlignSectionsFeatureCentroid/logs/archive_check.log`.
  This is what breaks the circularity concern for the Small IN100 path: the shift values the test
  path produces are confirmed against an implementation that is neither the test nor DREAM3D 6.5.171.

## Regenerated to fix a circular-oracle situation?

No. The archive is retained unchanged. The circular part of it — the SIMPLNX-generated
`output_align_sections_feature_centroids.dream3d` shift arrays — is simply no longer compared against:
the `output test` case that used it was retired on 2026-08-21 and replaced by thirteen hand-derived
Class 1 oracle test cases plus the independent 6.6.331 CSV cross-check described above. The file
remains in the archive because the archive is not being re-cut.

## Related archive retirement

The separate `6_6_align_sections_feature_centroids.tar.gz` download was removed from
`src/Plugins/SimplnxCore/test/CMakeLists.txt` on 2026-08-21. No test referenced it, and the exemplar
file of that name lives inside this archive. It was almost certainly the pre-#1237 archive, left
behind when #1237 introduced this superset.
