## How it was generated

PR #400 registers the archive and adds the example pipeline now at `src/Plugins/SimplnxCore/pipelines/ReplaceElementAttributesWithNeighbor.d3dpipeline`. That pipeline reads `Data/Small_IN100/Slice_1.ang`, transforms and crops the data, runs neighbor replacement, and writes a `.dream3d` file. The archive consumer loads `6_6_replace_element_attributes_with_neighbor.dream3d` twice, once as filter input and once as the reference.

The independent inputs are hand-constructed in `BuildSyntheticDataStructure()` in `src/Plugins/SimplnxCore/test/ReplaceElementAttributesWithNeighborValuesTest.cpp`. They use a 3×3×3 `ImageGeom`, a float32 `Confidence Index` array, and an int32 `Marker` array initialized to linear indices. The threshold is 0.5. Origin and spacing do not enter this neighbor-index algorithm; the cubic fixture checks opposite corners and the center, but does not distinguish axis lengths.

## Canonical oracle output

The archive supplies a stability comparison, not an independent replacement oracle. Classes 1 and 4 are encoded directly in the synthetic test.

| DataPath | Source of expected values |
|---|---|
| `DataContainer/Cell Data/*` | Archive regression: compare the filtered data with the same file loaded as the reference. |
| `Image3D/CellData/Confidence Index` | Class 1 expected replacement values; Class 4 threshold saturation after loop completion. |
| `Image3D/CellData/Marker` | Class 4 check that replacement changes the center marker from 13. |

The analytical fixtures use `index = x + 3*y + 9*z`:

| Index | Coordinates | Purpose |
|---|---|---|
| 0 | (0,0,0) | Missing -X, -Y, and -Z neighbors |
| 13 | (1,1,1) | Six valid face neighbors |
| 26 | (2,2,2) | Missing +X, +Y, and +Z neighbors |

In the LessThan section, these three cells start at 0.1 and all others start at 0.9. Each failing cell has a passing face neighbor. Each becomes 0.9, and the next pass finds no failing cells. The test checks all 27 values against the threshold, all three replacement values, and `Marker[13] != 13`.

The GreaterThan section reverses the values: the three selected cells start at 0.9 and all others at 0.1. Each selected cell becomes 0.1. The test checks all 27 values against the threshold and the three exact replacement values.

The single-pass section starts with only cell 13 at 0.1. It has six passing neighbors at 0.9, so its expected output is 0.9.

The surrounded-center section starts with bad cells `{4,10,12,13,14,16,22}` and disables the loop. All six neighbors of cell 13 fail the threshold during selection. Its source mark stays -1 and its value stays 0.1. Each surrounding cell has a passing exterior neighbor and becomes 0.9. The test checks the center and all six surrounding values.

Equal passing candidates exercise the strict best-value comparison. The tests do not assert the exact marker chosen under a tie. They do not directly test the float64 precision correction or a nonnumeric sibling.

The three ordinary test cases run in Linux, macOS, and Windows in-core builds. All pass in CI at `419f9db35`. The hidden `Generate Test Data` case writes inputs and does not execute replacement.
