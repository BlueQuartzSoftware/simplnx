## Contents relevant to this filter

`6_6_stats_test_v2.dream3d` is in the legacy (`DataContainers`) layout. One `ImageGeom` at `DataContainer`, dimensions 80 x 80 x 117 = **748,800 cells**, spacing `(0.25, 0.25, 0.25)`, holding a full Small IN100 reconstruction plus the outputs of most SimplnxCore feature-statistics filters.

The four arrays this filter's test touches, all in `DataContainer/CellData`:

| Array | Type | Role |
|---|---|---|
| `FeatureIds` | int32 | filter input. `min 1, max 619`, and **no cell has an id <= 0** — see the coverage caveat below |
| `GBManhattanDistances` | int32 | expected output, boundary tier |
| `TJManhattanDistances` | int32 | expected output, triple-line tier |
| `QPManhattanDistances` | int32 | expected output, quadruple-point tier |

`CellData/NearestNeighbors` (int32 x 3) is also present. It is the legacy filter's *internal* nearest-seed bookkeeping, written out because the generating run set `SaveNearestNeighbors = 1`. SIMPLNX has no equivalent output array, so the unit test does not consume it — but it turned out to be the single most useful artifact in this archive for V&V purposes (see *Canonical oracle output*).

## How it was generated

The generating pipeline is **embedded in the `.dream3d` file itself** (`/Pipeline/Pipeline`), so the provenance is self-documenting. It is a standard Small IN100 reconstruction (`ReadH5Ebsd`, `MultiThresholdObjects`, `ConvertOrientations`, `AlignSectionsMisorientation`, `IdentifySample`, `AlignSectionsFeatureCentroid`, `BadDataNeighborOrientationCheck`, `NeighborOrientationCorrelation`, `EBSDSegmentFeatures`, `MergeTwins`, `MinSize`, `MinNeighbors`, ...) followed by the full feature-statistics battery.

**Both documented deviations are structurally out of reach of this configuration**, which is why the archive agrees with SIMPLNX despite them:

- `ComputeEuclideanDistMapFilter-D1` (bad-data cells: legacy float `0.0` vs SIMPLNX `-1`) needs float32 mode; this run is Manhattan. It additionally needs a bad-data region, and the archive's `FeatureIds` has none.
- `ComputeEuclideanDistMapFilter-D2` (legacy's zero-initialised `NearestNeighbors` producing spurious seeds) needs a lower-tier toggle to be **off**; this run has all three on.

### The circularity concern, and how it was resolved

The `SimplnxCore::ComputeEuclideanDistMap` test compares the filter's freshly computed maps against sibling arrays *of the same name inside the same file*. On its face that is a circular oracle: legacy and SIMPLNX share the algorithm, so the archive's arrays were produced by an implementation of the very code under test.

The circle was broken during the 2026-08-20 V&V pass by re-deriving all three Manhattan maps **and** the internal `NearestNeighbors` array from `FeatureIds` alone, using an independent reimplementation of the seed rule, the layer-synchronous propagation and the `+Z > +Y > +X > -X > -Y > -Z` tie-break (`ww_work/ComputeEuclideanDistMap/archive_oracle.py`, a vectorised port of `oracle.py`). Result:

| Array | Seeds | Max distance | Oracle vs archive |
|---|---|---|---|
| `GBManhattanDistances` | 248,817 | 14 | **exact match, 748,800 / 748,800 cells** |
| `TJManhattanDistances` | 41,940 | 19 | **exact match, 748,800 / 748,800 cells** |
| `QPManhattanDistances` | 3,684 | 27 | **exact match, 748,800 / 748,800 cells** |
| `NearestNeighbors` (all 3 components) | — | — | **exact match, 748,800 / 748,800 cells** |

Coordination-size histogram of the input, for reference: `n == 0` 499,983 cells; `n == 1` 206,877; `n == 2` 38,256; `n == 3` 3,559; `n == 4` 123; `n == 5` 2.

So the archive is genuine, independently reproducible legacy output at production scale, and the retained test is a real Class 2 regression oracle rather than a tautology. The `NearestNeighbors` match is the stronger of the two results: it confirms the tie-break rule cell-by-cell on 748,800 cells, not just on the hand fixtures.

## Coverage caveats — do not treat this archive as sufficient on its own

1. **No bad-data region.** Every cell has `FeatureIds >= 1`. The `-1` sentinel path, the `featureId >= 0` neighbour-admission rule (id 0 counting as a distinct neighbouring feature), and deviation D1 are all invisible to this archive. Measured, not asserted: the mutation sweep's M4 (`>= 0` tightened to `> 0`) is **not** caught by this test, while it kills six Class 1 sections on fixture A.
2. **Manhattan mode only.** No float32 array is stored, so nothing in this archive exercises the euclidean conversion, the coordinate decode, or the tie-break's *visible* consequence. Measured: the mutation sweep's M6 (tie-break reversed) is **not** caught by this test. That is expected and provable — the tie-break changes only which seed is *recorded*, and every neighbour available in a given propagation pass carries the same pass number, so the Manhattan values are identical either way.
3. **All three toggles on.** Deviation D2 cannot manifest.
4. **Isotropic spacing** `(0.25, 0.25, 0.25)`, so nothing here would expose an axis mix-up in the coordinate decode.

Those four gaps are exactly what the inlined Class 1 and Class 4 fixtures in `ComputeEuclideanDistMapTest.cpp` exist to close. The archive's value is scale and realism (748,800 cells, 619 features, real EBSD topology, distances up to 27), not discrimination.
