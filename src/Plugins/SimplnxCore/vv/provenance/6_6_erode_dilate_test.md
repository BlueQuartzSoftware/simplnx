## How it was generated

A local proof version produced the archive through pipelines embedded at `/Pipeline/Pipeline` in the `.dream3d` files. The mask pipeline imports slices 1 through 20 from `SmallIN100.h5ebsd`, reconstructs the data, and copies `Input Data` into two exemplar containers. Steps 08 and 10 run `ErodeDilateMask` with `Direction` 1 (erode) and 0 (dilate), respectively; both use two iterations with X, Y and Z enabled. Step 11 writes the mask file with `DataContainerWriter`.

| File in `6_6_erode_dilate_test/` | Consumer |
|---|---|
| `6_6_erode_dilate_bad_data.dream3d` + `.xdmf` | `ErodeDilateBadDataFilter` |
| `6_6_erode_dilate_mask.dream3d` + `.xdmf` | `ErodeDilateMaskFilter` |
| `6_6_erode_dilate_coordination_number.dream3d` + `.xdmf` | `ErodeDilateCoordinationNumberFilter` |

The embedded annotations record a local change that disables feature-ID randomization. Their statement about using one slice conflicts with the import settings and the stored 189×201×20 geometries in the mask and bad-data files. The stored mask arrays have shape `(20, 201, 189, 1)` and type `uint8`.

The bad-data file has an 18-step embedded pipeline. Steps 12 and 15 run `ErodeDilateBadData` with `Direction` 1 and 0, two iterations, all axes enabled and no ignored arrays. Any archive regeneration must account for all three consumers.

## Oracle provenance (Classes 2, 3, 5 only)

ErodeDilateMaskFilter uses Class 1, so no external correctness-oracle provenance block is required. The following artifacts document the separate legacy comparison.

Run against DREAM.3D v6.5.171 on 2026-08-18: 28 of 28 mask cases match. `vv_work:ErodeDilateMaskFilter/ReadMe.md` identifies the stock `PipelineRunner` and records the run date. `vv_work:ErodeDilateMaskFilter/results_compare.txt` gives the 28 element-wise matches from `vv_work:ErodeDilateMaskFilter/compare.py`.

The comparison uses a 5×5×1 centre seed and a 3×3×3 hollow cube. Each fixture runs dilation and erosion for one iteration on each of seven non-empty axis combinations. The Z-only cases on the single-slice fixture preserve the input; the cube supplies the Z-direction evidence.

`vv_work:ErodeDilateMaskFilter/results_oracle_check.txt` confirms that both binaries match five hand-derived masks from `vv_work:ErodeDilateMaskFilter/oracle_check.py`:
