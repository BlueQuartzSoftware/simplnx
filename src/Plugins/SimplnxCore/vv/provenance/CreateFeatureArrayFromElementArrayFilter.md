## How it was generated

The shared archive contains `6_5_test_data_1_v2.dream3d`, which the tests load as Small IN100. The two tests read element arrays and compare the generated feature arrays with the stored ConfidenceIndex and IPFColors arrays. Separate hand-constructed C++ inputs supply the independent oracle; these fixtures do not use archived expected values.

The independent fixtures are defined in `src/Plugins/SimplnxCore/test/CreateFeatureArrayFromElementArrayTest.cpp`. AF-1 through AF-9 use small arrays with explicit FeatureIds. `Bulk last-value boundary oracle` uses 65,538 element tuples, three unequal components, a feature first seen in the final tuple, and a gap feature. This filter does not use geometry, so axis dimensions and origins do not enter its oracle.

**Saved legacy comparison**

**Release-source evidence**

The legacy source is `Source/SIMPLib/CoreFilters/CreateFeatureArrayFromElementArray.cpp` in SIMPL at `0afaa6854ac0ef27df17278e11be711f74f77b90`. This is the last SIMPL commit on or before the DREAM.3D `v6.5.171` tag date, 2026-05-27T16:41:12-04:00. Its `execute()` rejects undersized and oversized feature matrices with `-5555` and `-5556`. It does not reject negative IDs or unequal input tuple counts. It has neither the empty-array maximum lookup nor the unconditional feature-matrix resizing that caused the SIMPLNX-only defects.

Each release source was inspected with `git show upstream/release/v<version>:<path>` for v7.0.0, v7.0.1, v7.0.2, v7.0.3, v7.2.0, v7.2.1, v7.2.2, v7.4.0, v7.4.1 and v7.4.2. Source paths below are relative to `src/Plugins/SimplnxCore/src/SimplnxCore/Filters/`.

| Releases | Source | D2: negative IDs | D3: unequal tuples | D4: empty IDs | D5: truncation |
|---|---|---|---|---|---|
| DREAM3D-NX v7.0.0 through v7.4.0 | `CreateFeatureArrayFromElementArrayFilter.cpp` | No rejection | No length check | Maximum lookup indexes an empty store | Unconditional resize |
| DREAM3D-NX v7.4.1 | `CreateFeatureArrayFromElementArrayFilter.cpp`; `Algorithms/CreateFeatureArrayFromElementArray.cpp` | No rejection | No length check | Maximum lookup indexes an empty store | Unconditional resize |
| DREAM3D-NX v7.4.2 | Same paths | Error `-81880` | Error `-81883` | Error `-81882` | Growth-only resize and error `-81881` |

PR #1695 (`fa31947b5`) supplies all four corrections. DREAM.3D v6.5.171 was affected by D2 and D3; it was not affected by D4 and D5. Current chunked execution retains the four protections. D1 keeps its original ID spelling, `CreateFeatureArrayFromElementArray-D1`; D2 through D5 use `CreateFeatureArrayFromElementArrayFilter-D<N>`.

## Canonical oracle output

The archive arrays supply regression expectations. Independent canonical values are encoded in the C++ fixtures.

| DataPath | Source of expected values |
|---|---|
| `/DataContainer/CellFeatureData/ConfidenceIndex` | Stored Small IN100 regression array; used by the one-component archive test. |
| `/DataContainer/CellFeatureData/IPFColors` | Stored Small IN100 regression array; used by the three-component archive test. |
| `/ParentGroup/FeatureData/OutputFeatureArray` | Class 1 hand derivation in AF-1, AF-2, AF-3, AF-6 and `Bulk last-value boundary oracle`. |

| Fixture | Expected output or error |
|---|---|
| AF-1 | float32 `[5,10,20]`; no warnings. |
| AF-2 | float32 `[0,15,20]`; exactly one warning. |
| AF-3 | uint8 `[[0,0,0],[10,20,30],[40,50,60]]`; no warnings. |
| AF-4 | All-negative IDs → `-81880`. |
| AF-5 | Growing a two-tuple matrix to four would truncate its five-tuple child → `-81881`. |
| AF-6 | float32 `[5,0,30]`; no warnings; the unused feature stays zero. |
| AF-7 | Empty IDs → `-81882`. |
| AF-8 | Mixed negative/nonnegative IDs → `-81880`. |
| AF-9 | Four element tuples and two ID tuples → preflight error `-81883`. |
| Bulk last-value boundary oracle | int32 `[[0,0,0],[7,70,700],[0,0,0],[2,20,200]]`; exactly one warning `-1000`. |

For each mapped feature, its last element tuple supplies the expected values. Unused output tuples are zero. AF-1, AF-2, AF-3 and AF-6 assert output tuple count, data type and component count. The bulk fixture asserts tuple count, component count, all 12 values and the warning code. Its three changed components check suppression of additional warnings. No successful fixture tests a matrix that already has enough tuples; the archive tests also start with a one-tuple matrix.
