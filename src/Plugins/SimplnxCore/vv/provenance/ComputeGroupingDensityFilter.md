## How it was generated

The archive's `generate_inputs.py` constructs a synthetic 20×5×1 image with five populated features and two populated parents, plus index-zero placeholders. It writes one legacy-format input file for both implementations. Four JSON pipelines run `FindGroupingDensity` in a local proof version; one SIMPLNX pipeline runs all four option combinations. `compare_outputs.py` compares the resulting arrays, and the README records Michael Jackson's review of the inputs and outputs.

## Canonical oracle output

For each parent, form the union of its assigned features and their contiguous neighbors. Include non-contiguous neighbors when selected. Sum each feature volume once. Divide the parent volume by that sum; use `-1.0f` when the sum is zero.

For the contiguous-only input, parent 1 touches `{1,2,3,4}` and parent 2 touches `{3,4,5}`. Both sums equal 70. With non-contiguous neighbors enabled, each parent touches `{1,2,3,4,5}` and the sum equals 100.

The following DataPaths refer to arrays in the combined SIMPLNX output. The HDF5 file contains them below `/DataStructure`.

| DataPath | Source of expected values |
|---|---|
| `/DataContainer/ParentData/GroupingDensities_NC0_CF0` | Class 1: `[0, 45/70, 55/70]` |
| `/DataContainer/ParentData/GroupingDensities_NC0_CF1` | Class 1: `[0, 45/70, 55/70]` |
| `/DataContainer/ParentData/GroupingDensities_NC1_CF0` | Class 1: `[0, 45/100, 55/100]` |
| `/DataContainer/ParentData/GroupingDensities_NC1_CF1` | Class 1: `[0, 45/100, 55/100]` |
| `/DataContainer/FeatureData/CheckedFeatures_NC0_CF1` | Class 1: `[0, 1, 1, 2, 2, 2]` |
| `/DataContainer/FeatureData/CheckedFeatures_NC1_CF1` | Class 1: `[0, 2, 2, 2, 2, 2]` |

The result file records float32 densities `0.6428571343421936`, `0.7857142686843872`, `0.44999998807907104` and `0.550000011920929`. These equal the float32 values of the four ratios above.

Checked-feature selection uses a strict `>` comparison against an initial claimed volume of zero. Parent 2 has volume 55 and replaces parent 1, whose volume is 45, on shared features. Equal positive parent volumes keep the first claimant; the fixture does not test equal volumes. A zero-volume parent does not replace an initial zero claim.

`test/ComputeGroupingDensityTest.cpp` compares all generated densities with the archive and compares checked-feature IDs when enabled. `CompareDataArrays<float32>` in `test/UnitTestCommon/include/simplnx/UnitTest/UnitTestCommon.hpp` accepts absolute differences up to `0.0001`; integer comparison is exact. The exemplar test is therefore not a bitwise floating-point test.

The same test checks Class 4 properties: parent-zero density is zero; each other density is positive or the sentinel and at most one; checked-feature IDs are in range; feature zero is unclaimed. The upper density bound assumes that parent volumes agree with assigned feature volumes, as they do in this fixture. The separate empty-parent test supplies feature volumes 5 and 10 to parent 1 and no features to parent 2. It checks density 1 within relative tolerance `0.0001` and sentinel `-1.0f` exactly.

The hidden HDF5 fixture encodes an additional Class 1 construction in C++. Features 2 and 3 have volumes 4 and 8 and belong to parent 1, whose volume is 12. Shared neighbor 4 adds volume 4 once, giving density `12/16 = 0.75`. Optional neighbor 8 adds volume 8, giving `12/24 = 0.5`. Feature indices 2 and 3 cross a three-tuple list boundary. Parent 2 stays at `-1.0f`, and the fixture checks the expected claims or absence of the disabled checked-feature array.
