## How It Was Generated

The `.dream3d` file contains an embedded DREAM3D-NX pipeline that documents the archive construction. The pipeline reads the predecessor `6_5_test_data_1/6_5_test_data_1.dream3d`, copies `DataContainer` to `DataContainer2`, and changes the copied **Image Geometry** origin to `[-10.0, 50.0, 30.0]` and spacing to `[0.5, 0.5, 0.5]`. It then runs `CropImageGeometryFilter` for all seven nonempty combinations of the X, Y, and Z crop dimensions and writes the v2 `.dream3d` file.

No standalone copy of the generating pipeline was committed to this repository. The embedded pipeline is the available generation record. The exact DREAM3D-NX build and the person who executed it are unknown.

## Canonical Oracle Output

No array in this archive is the canonical correctness oracle for `RequireMinNumNeighborsFilter`. The archive is an input fixture for that test. The expected `NumElements` sequence is derived in the test from the pre-filter `NumElements` values and the independently computed neighbor-count threshold, while the primary V&V oracle is the inline Class 1 analytical fixture with Class 4 invariants.

## Regenerated to Fix a Circular-Oracle Situation?

No evidence indicates that this archive was regenerated to fix a circular oracle. Git history shows that v2 replaced `6_5_test_data_1.tar.gz` in PR #1021 while the crop-dimension test variants and their generated reference geometries were added.

The archive was not regenerated during the `RequireMinNumNeighborsFilter` V&V cycle and its arrays are not used as post-filter golden output for that filter. The previously hard-coded `NumElements` snapshot was a source-level test constant, not a regenerated archive; the current test derives the expectation from pre-filter inputs instead.
