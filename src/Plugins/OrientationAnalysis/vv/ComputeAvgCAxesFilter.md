### Algorithm summary

For each voxel `i` with `cellPhase[i] > 0` AND phase is `Hexagonal_High` or `Hexagonal_Low`:
1. Take voxel quaternion → orientation matrix (post-PR-#1472: `ebsdlib::QuaternionDType.toOrientationMatrix()`) → transpose → multiply by `c_crystal = [0,0,1]` to get the voxel's lab-frame c-axis (active rotation)
2. Increment `counter[currentFeatureId]++` *(post-PR-#1438: increment now BEFORE the antipodal-flip test — see silent change #2 below)*
3. Compute running average `curCAxis = avgCAxes[fId] / counter[fId]`
4. `w = CosBetweenVectors(c1_voxel, curCAxis)`; if `w < 0` flip sign of `c1_voxel` (antipodal-flip for hex c-axis equivalence)
5. Accumulate: `avgCAxes[fId] += c1_voxel`

Per-feature normalization (after the per-cell loop):
- For each hex feature: `avgCAxes[fId] /= norm(avgCAxes[fId])` (renormalize to unit vector)
- **Rescue case**: if `counter[fId] == 0` (all voxels masked / non-hex), output set to `(0, 0, 1)` exactly (line 162-164)
- For non-hex feature: output is NaN

**Restrictions**: only `Hexagonal_High` / `Hexagonal_Low` Laue groups; mixed-phase → warning `-76403` + NaN; no hex phase at all → error `-76402`.

**Threading**: Single-threaded; cancel checks in 2 loops (PR #1582). All accumulation now in `Eigen::Vector3d` / `OrientationD` / `QuatD` / `Matrix3dR` post-PR-#1438.

### Recommended starting point

**Class 3 (Paper-based) primary** — Rowenhorst et al. 2015 (*"Consistent representations of and conversions between 3D rotations"*, Modelling Simul. Mater. Sci. Eng. 23 083501, DOI `10.1088/0965-0393/23/8/083501`) for the quaternion → orientation-matrix conversion. Bunge "Texture Analysis in Materials Science" for the c-axis-from-orientation derivation. The algorithm is: rotate `[0,0,1]` by per-voxel quaternion (transpose the orientation matrix to get active rotation), accumulate, renormalize. Both citations are canonical for this math.

**Class 4 (Invariant) companion** — strong invariants:
1. **Unit-norm**: `||avgCAxes[fId]|| == 1` for any feature with at least one hex voxel and at least one non-zero contribution
2. **Identity case**: feature whose voxels all share quaternion `q` → `avgCAxis(feature) == rotate([0,0,1], q)` exactly
3. **NaN propagation**: non-hex feature → output is NaN
4. **Rescue case**: feature with `counter == 0` (all voxels masked) → output is exactly `(0, 0, 1)` (per algorithm line 162-164)
5. **Antipodal symmetry**: a feature's avg c-axis is uniquely defined up to sign — running the same data with all quaternions inverted produces ±avgCAxis

**Class 1 (Analytical) supplemental** — hand-derivable spot check:
- Single-voxel hex feature with quaternion `(1, 0, 0, 0)` (identity) → `avgCAxis == (0, 0, 1)` to within float epsilon (Identity matrix · `[0,0,1]` = `[0,0,1]`)

### Antipodal-flip note (load-bearing physics + Phase-9 D2 source)

Hex symmetry treats `c` and `−c` as equivalent. The algorithm uses a running-average dot-product test (`if w < 0 then c1 *= -1`) to keep contributions co-aligned. PR #1438 changed *when* this test runs for the first voxel of each feature (Phase 1 §"Pre-flagged silent changes" #2). This is the most subtle source of legacy disagreement — Phase 5 Fixture E specifically pins the new behavior.

#### D1 — Float → double accumulation (Medium)

> **Deviation ID:** `ComputeAvgCAxes-D1`
> **Filter UUID:** `453cdb58-7bbb-4576-ad5e-f75a1c54d348`
> **Symptom:** SIMPLNX output average c-axis vectors differ from SIMPL `FindAvgCAxes` in the 6th–7th decimal place across most features.
> **Root cause:** Precision. PR #1438 changed accumulators from `Eigen::Vector3f` / `OrientationF` / `QuatF` / `Matrix3fR` to all `*D` variants. Final output is still cast to `float32`, but intermediate sums are double-precision.
> **Affected users:** Anyone bit-comparing average c-axis vectors against legacy DREAM3D output. Magnitudes and inter-feature relationships are unaffected.
> **Recommendation:** **Trust SIMPLNX.** Double-precision accumulation is standard for averaging directional data. Document the precision change in the user-facing docs.

#### D2 — Antipodal-flip first-voxel behavior (HIGH-priority — silent sign change)

> **Deviation ID:** `ComputeAvgCAxes-D2`
> **Filter UUID:** `453cdb58-7bbb-4576-ad5e-f75a1c54d348`
> **Symptom:** For features whose first hex voxel happens to lie on the antipodal half of the c-axis hemisphere, the average c-axis sign may flip vs. legacy.
> **Root cause:** PR #1438 moved `counter[currentFeatureId]++` to BEFORE the running-average antipodal-flip test. In legacy, `counter` was 0 for the first voxel → `curCAxis = avgCAxes/0 = inf/NaN` → `CosBetweenVectors(c1, NaN-vec)` likely passed `w < 0` → first voxel always flipped. In SIMPLNX (post-#1438), increment first → `curCAxis = (0,0,0)` → `CosBetweenVectors(c1, zero-vec) = 0` → first voxel never flipped.
> **Affected users:** Any user comparing per-feature c-axis sign against legacy. Magnitude is unchanged; only the sign (antipodal hemisphere choice) can differ. Hex symmetry treats `c ≡ −c` so downstream texture analyses are typically unaffected — but per-feature scalar comparisons are.
> **Recommendation:** **Trust SIMPLNX.** Legacy behavior was a divide-by-zero artifact. Verify by reading SIMPL `FindAvgCAxes` source.
> **Status:** Locked by Phase-8 Fixture E.

#### D3 — Error-code renumbering + preflight warning surface change (Low, user-facing)

> **Deviation ID:** `ComputeAvgCAxes-D3`
> **Filter UUID:** `453cdb58-7bbb-4576-ad5e-f75a1c54d348`
> **Symptom:** A pipeline that previously produced preflight warning `-6401` ("Finding the average c-axes requires Hexagonal-Low or Hexagonal-High…") now produces no preflight warning; the message moved to a non-error `preflightUpdatedValues` info banner. Error codes `-6402` / `-6403` were also re-numbered to `-76402` / `-76403`.
> **Root cause:** PR #1438 reclassified the message from `Result<>::warnings()` to `preflightUpdatedValues` and re-numbered codes.
> **Affected users:** Anyone parsing pipeline logs by error code, or whose CI greps for the preflight warning text.
> **Recommendation:** **Trust SIMPLNX** (new behavior is more user-friendly). Note the error-code change in release notes.

#### D4 — EbsdLib 2.0 quat→om convention parity (Low, verify only)

> **Deviation ID:** `ComputeAvgCAxes-D4`
> **Symptom:** *(if observed)* output average c-axis vectors shift between SIMPLNX commits before and after PR #1472.
> **Root cause:** PR #1472 swapped `OrientationTransformation::qu2om<QuatD,OrientationD>` + `OrientationMatrixToGMatrixTranspose` for `ebsdlib::QuaternionDType.toOrientationMatrix()` + `oMatrix.transpose() * cAxis`. Mathematically equivalent IF EbsdLib 2.0 uses the same passive-rotation convention.
> **Recommendation:** Re-run the existing exemplar at the PR #1472 boundary; record any delta. If below `5e-7`, withdraw the deviation. Otherwise document.
