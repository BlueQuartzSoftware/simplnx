### Orientation convention

Quaternions follow the EbsdLib `(x, y, z, w)` Vector-Scalar order, where for a rotation of angle θ about unit axis `n`:

```
q = (sin(θ/2)·n_x, sin(θ/2)·n_y, sin(θ/2)·n_z, cos(θ/2))
```

The algorithm consumes each quaternion as a **passive** rotation matrix `R = qu2om(q)`. The crystal c-axis `[0, 0, 1]` (in the crystal reference frame) is rotated into the sample reference frame by the active operation `c_sample = R.transpose() @ [0, 0, 1]` (equivalent to using `R` as the active rotation when the convention starts from passive). The per-feature average is the arithmetic mean of all hex-cell c-axes belonging to that feature, with an antipodal-flip rule (`if c_i · running_sum < 0: c_i := -c_i`) to keep contributions in a coherent hemisphere, followed by per-feature normalization.

### Feature 7 — the diagnostic feature

Feature 7's cells have c-axes at `(0, 0, 1)`, `(0, √3/2, 1/2)`, and `(0, -√3/2, 1/2)`. The unweighted arithmetic mean is:

```
(0,  0,        1)
+ (0,  √3/2,    1/2)
+ (0, -√3/2,    1/2)
= (0,  0,        2)
/ 3 = (0,  0,    2/3)
```

magnitude `2/3 ≈ 0.6667` — the **unnormalized** value legacy 6.5.171 wrote. After SIMPLNX's per-feature normalize (added during the V&V cycle's Phase 7 refactor), the SIMPLNX output is `(0, 0, 1)` magnitude 1 — but only when the running-average antipodal-flip rule fires cleanly.

The antipodal-flip rule (`if c_i · running_sum < 0: c_i := -c_i`) is precision-sensitive at the cancellation boundary: when `running_sum` for cells 8-9 is `(0, √3/2, 3/2)`, evaluating `c_10 · running_sum = (0, -√3/2, 1/2) · (0, √3/2, 3/2) = -3/4 + 3/4 = 0` to mathematical precision but slightly positive or negative in IEEE 754 depending on accumulation order. SIMPLNX and 6.5.172 happen to compute it as positive (flip does NOT fire), producing `(0, √3/2, 1/2)` post-normalize; the unnormalized sum direction matches but legacy 6.5.171's unnormalized magnitude is `2/3`, not 1 — D2 surfaces here.

This was deliberately placed on the boundary to validate the Class 4 invariant `||AvgCAxes|| == 1.0` post-normalize (SIMPLNX side) and to surface D2's precision-sensitive boundary as a documented deviation rather than an unexplained difference.

## Regenerated to fix a circular-oracle situation?

**Yes.** This archive replaces the retired `7_2_AvgCAxis.tar.gz` (SHA512 not retained in this repo). The retired archive contained exemplar arrays whose reference values were produced by a "special build of DREAM3D 6.6.379 with micro-texture bug fixes" — i.e., reference values produced by a non-baseline DREAM3D build, not by an independent oracle. Per V&V policy line 33 ("'Legacy 6.5.171 produced this output' is never a valid oracle for correctness"), the retired archive failed the independence test even more sharply: it was a *modified* legacy build, not even the baseline. The hand-built Class 1 oracle in this archive is independent of any DREAM3D implementation, and is cross-validated by the three-way A/B confirming SIMPLNX matches the 6.5.172 backport bit-for-bit.

The `download_test_data` line for the retired archive was removed from `test/CMakeLists.txt` as part of the V&V cycle's retirement work; the new archive's `download_test_data` line + SHA512 are wired in at the same location.
