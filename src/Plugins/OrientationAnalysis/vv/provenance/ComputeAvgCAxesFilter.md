## How it was generated

Michael Jackson designed an 11-cell, 8-feature input with selected quaternions and two material phases. The generation record in PR #1631 identifies `compute_avg_c_axis/generate_inputs.py` as the script that creates `compute_avg_c_axis/data/compute_avg_caxes_inputs.dream3d`. The tests load this input and compare generated values with literal expectations in C++; they do not load output arrays as correctness references.

The input design is an 11×1×1 Image Geometry with three AttributeMatrices:

| AttributeMatrix | Tuple count | Arrays |
|---|---|---|
| `DataContainer/CellData` | 11 | `FeatureIds` (int32), `Phases` (int32), `Quats` (float32, four components) |
| `DataContainer/CellFeatureData` | 8 | Feature tuples F0 through F7; the test creates `ComputedAvgCAxes` here. |
| `DataContainer/CellEnsembleData` | 3 | `CrystalStructures`: placeholder, Hexagonal_High, Cubic_High |

The fixture varies the Y and Z components and uses several feature populations. All rotations are about X, so the expected X component is zero. The one-dimensional layout and zero X components do not test general three-axis orientation behavior. The algorithm uses arrays and feature assignments; it does not read image spacing or origin.

**Analytical construction**

For a quaternion representing angle θ about unit axis `n`, use `q = (sin(θ/2)n, cos(θ/2))`. The passive orientation matrix `R(q)` gives the sample C-axis as `R(q).T × (0,0,1)`. Process each feature's cells in cell-index order. Flip a contribution when its dot product with the running direction is negative. Normalize the final sum for each feature with at least one hexagonal contribution.

| Feature | Contributions | Expected result | Check |
|---|---|---|---|
| F0 | None | `(NaN,NaN,NaN)` | Three `isnan` assertions |
| F1 | Identity | `(0,0,1)` | Three component comparisons |
| F2 | +60° about X | `(0,√3/2,1/2)` | Three component comparisons |
| F3 | Three identity cells | `(0,0,1)` | Three component comparisons |
| F4 | Identity and 180° about X | `(0,0,1)` after the antipodal flip | Three component comparisons |
| F5 | None | `(NaN,NaN,NaN)` | Three `isnan` assertions |
| F6 | One Cubic_High cell, excluded | `(NaN,NaN,NaN)` | Three `isnan` assertions |
| F7 | Identity, +60° X, -60° X | Unit magnitude | Three non-NaN checks and one magnitude comparison |

Component and magnitude comparisons use an absolute margin of `1e-5`. This is a dimensionless vector tolerance, not an angular tolerance. A separate dynamic section checks unit magnitude for F1, F2, F3, F4, and F7. The five ordinary test cases use the supplied in-core CI result. All pass in CI at `419f9db35`.

**F7 sign-boundary derivation**

The first two ideal axes sum to `(0,√3/2,3/2)`. The third axis `(0,-√3/2,1/2)` has dot product `-3/4 + 3/4 = 0` with that sum. Rounding can determine whether the strict negative-cosine branch fires.

| Sign decision for the third axis | Mean before normalization | Direction after normalization |
|---|---|---|
| Keep its sign | `(0,0,2/3)` | `(0,0,1)` |
| Flip its sign | `(0,1/√3,1/3)` | `(0,√3/2,1/2)` |

Both pre-normalization means have magnitude `2/3`. Both normalized directions have magnitude 1, but their angle is 60°. The test asserts magnitude for F7 and does not assert either direction. This derivation explains D2 without using a legacy output as an oracle.

**Separate boundary fixture**

`genuine HDF5 4096-block tail oracle` constructs its input in C++ and does not use this archive. It has 4,097 cells, including 4,095 background cells. Feature 1 receives an identity contribution at index 4,095 and a +60° X contribution at index 4,096. Their normalized mean is `(0,1/2,√3/2)`.
