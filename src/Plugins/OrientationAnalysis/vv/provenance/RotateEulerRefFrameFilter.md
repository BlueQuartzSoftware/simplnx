## How it was generated

`ASCIIData/ReadMe.md` identifies Small IN100 as the source dataset. DREAM.3D cropped X indices 41–100, Y indices 41–120 and Z indices 0–99, giving 60×80×100 cells. It generated the rotated Euler values with a 30° rotation about `(1,1,1)`. The test imports `ASCIIData/EulerAngles.csv` and `ASCIIData/EulersRotated.csv`; it uses the latter for regression comparisons.

The independent fixtures are separate from the archive. `AnalyticalFixtures::CreateEulerArray()` constructs the input arrays, and `AnalyticalFixtures::k_Fixtures` contains eight fixed expected triples. `vv_work:RotateEulerRefFrameFilter/rotate_euler_ref_frame_oracle.py` implements Rodrigues rotation and Euler conversion equations without importing EbsdLib or SIMPLNX.

## Canonical oracle output

| DataPath | Source of expected values |
|---|---|
| `CellData/EulerAngles` | Class 1: F1–F7 use closed-form derivations; F8 evaluates the same independent matrix equations in the NumPy script. The eight triples are stored in `src/Plugins/OrientationAnalysis/test/RotateEulerRefFrameTest.cpp`. |
| `CellData/EulerAngles` | Class 4: inclusive float32 range bounds, inverse-rotation recovery and 45°+45° equivalence to 90°. |
| `EulersRotated` | Values imported from `ASCIIData/EulersRotated.csv`. This is a DREAM.3D regression reference, separate from the independent oracle. |

For Bunge passive orientations, `v_crystal = g · v_sample`. A reference-frame rotation gives `g′ = g · R_active(n,w)`, where Rodrigues' formula defines `R_active`. A Z-axis rotation therefore subtracts `w` from `phi1` modulo `2π`. F4 and F5 check the same X rotation with unit and non-unit axes; F7 checks the `(1,1,1)` axis. F8 uses unequal Euler components `(0.8,1.1,0.4)` and a 45° Y rotation.

F1 is the zero-Phi singular case. F6 is a zero-angle rotation with input Phi equal to 1 radian, so it does not exercise that singularity. The analytical test uses `1e-5` rad tolerance. The round-trip and composition checks use `1e-4` for two float32 store/load passes. Float32 rounding makes the range limits inclusive.

The five ordinary test cases pass on Linux, macOS and Windows in the supplied CI evidence. All pass in CI at `419f9db35`.

**Precision and representation notes**

- `RotateEulerRefFrameFilter-N1`: the tagged DREAM.3D v6.5.171 source uses float angle conversion, `FOrientTransformsType` and float matrix operations. Current SIMPLNX uses double angle conversion and double orientation matrices. The measured differences above are within the test tolerance; the source does not support attributing them solely to angle conversion.
- `RotateEulerRefFrameFilter-N2`: the 2026-07-03 summary records `phi1` near 0 in SIMPLNX and near `2π` in DREAM.3D at an exact wrap boundary. Compare such angles modulo `2π`.
- `RotateEulerRefFrameFilter-N3`: the zero-axis validation difference is now recorded as the confirmed defect `RotateEulerRefFrameFilter-D1`. The original claim that DREAM.3D always divides a zero axis by zero is contradicted by its float normalization helper.

## Oracle provenance (Classes 2, 3, 5 only)

The primary oracles are Classes 1 and 4. The independent NumPy script evaluates the matrix equations and cross-checks the analytical values. Its source cites Rowenhorst et al., “Consistent representations of and conversions between 3D rotations,” *Modelling and Simulation in Materials Science and Engineering* 23 (2015), 083501, equations A.5 and A.9, DOI `10.1088/0965-0393/23/8/083501`. All inputs are deterministic; no random seed is used.
