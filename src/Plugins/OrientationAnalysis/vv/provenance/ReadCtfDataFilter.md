## How it was generated

The former test loaded `6_6_read_ctf_data.dream3d` and imported `Cugrid_after 2nd_15kv_2kx_2.ctf` from the archive. It compared the imported arrays with the stored arrays. The current fixtures are hand-authored CTF strings in `src/Plugins/OrientationAnalysis/test/ReadCtfDataTest.cpp`; `MakeToyCtf()` assembles them and `WriteCtfFile()` writes the inputs. They include a 3×2 two-phase grid, a three-phase conversion grid, and a 2×2×2 multi-slice grid.

No archived output is used as a correctness oracle. The paths below refer to the inline fixtures; expected values are literals in the test source.

The 12 default test cases run on Linux, macOS, and Windows. All pass in CI at `419f9db35`. The conversion fixture asserts all 18 Euler values for each of four modes and includes both hexagonal Laue classes. Values 7.125, 3.375, 6.75, and shifted 37.125 degrees distinguish float32 arithmetic from double-intermediate conversion.

The stock comparison ran on 2026-07-24. `vv_work:ReadCtfDataFilter/ReadMe.md` identifies the official DREAM.3D v6.5.171 PipelineRunner. `vv_work:ReadCtfDataFilter/results/compare_ab_2026-07-24.txt` records four cases: `toy_ff`, `toy_tt`, `cugrid_tt`, and `toy3d_ff`. Four of four cases match outside D1 and D2; none matches in every array because each contains unindexed points. The Cugrid comparison has 116,050 phase differences and 116,050 Euler-component differences, with the other 543,950 Euler components equal. The 3D case has two phase differences and 24 equal Euler components.

The same ReadMe records two stock crashes for missing BS and empty phase definitions, and acceptance of phase 7 with only two phases. The 2026-09-17 local proof version adds three guards, rejects those malformed inputs, and preserves 60 datasets across four well-formed cases. Evidence: `vv_work:ReadCtfDataFilter/LegacyPatch.md`, `vv_work:ReadCtfDataFilter/scripts/run_legacy_proof_guard.py`, and `vv_work:ReadCtfDataFilter/scripts/run_wellformed_proof.py`. `vv_work:ReadCtfDataFilter/results/release_matrix.md` separately records single-slice output in DREAM3D-NX v7.4.1 and full-volume output in v7.4.2.
