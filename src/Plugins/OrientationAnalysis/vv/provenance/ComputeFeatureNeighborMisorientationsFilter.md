## How it was generated

The retired regression test read `6_6_stats_test_v2.dream3d` as Small IN100 data and compared a calculated neighbor list with its stored `MisorientationList`. PR #1631 replaced that test with hand-constructed data in `src/Plugins/OrientationAnalysis/test/ComputeFeatureNeighborMisorientationsTest.cpp`. `AnalyticalFixtures::CreateScaffold()` creates the geometry, feature arrays, ensemble arrays, and empty neighbor lists. `SetAvgQuat()` and `QuatFromPhi1Deg()` supply rotations about Z as float32 quaternions in `(x,y,z,w)` order.

## Canonical oracle output

The correctness oracle is in the C++ test source. Stored archive outputs and legacy outputs do not define its expected values.

The scaffold has a 1×1×1 image with unit spacing and zero origin. The algorithm reads feature data rather than cell coordinates, so image dimensions and origin do not affect this oracle. `numFeatures` includes background feature zero. Outputs are named `MisorientationListOut` and `AvgMisorientationsOut` under `ImageGeometry/FeatureData`.

The Class 1 fixtures use cubic rotations of 0°, 5°, and 10°. These differences are below the 45° cubic fold, so the expected angles are 5° and 10°. Phase 1 has crystal structure 1 (`Cubic_High`). In mixed-phase fixtures, phase 2 has crystal structure 0 (`Hex_High`), so its neighbors are excluded by crystal-structure mismatch.

| Fixture | Input at focal feature 1 | Expected output |
|---|---|---|
| `Class 1 - Single Phase Two Neighbors` | Four tuples including background; neighbors `[2, 3]`, at 5° and 10° | List `[5°, 10°]`; mean 7.5° |
| `Class 1 - Mixed Phase Neighbors (exposes divisor bug)` | Five tuples; neighbors `[2, 4, 3]`; feature 4 has the incompatible hexagonal structure | List `[5°, NaN, 10°]`; mean 7.5° |
| `Class 1 - Mismatch Last Order` | Same data with neighbors `[2, 3, 4]` | List `[5°, 10°, NaN]`; mean 7.5° |
| `Class 4 - Invariants` | Five tuples; neighbors `[4, 2, 3]`; compatible rotations 7.5° and 12°, with feature 4 incompatible | Three entries; finite angles in `[0°, 62.8°]`; mean equals their sum divided by their count |

Feature 4 has a 99° input rotation in the mixed fixtures. The angle is not calculated for its incompatible pair. The invariant test checks only feature 1 and requires a positive finite-entry count; it does not assert an all-incompatible or empty-list average.

The hidden `genuine HDF5 1MiB-chunk tail oracle` constructs 65,537 feature tuples. It uses 65,536 quaternion tuples per physical chunk, then a one-tuple tail. Features 65,535 and 65,536 have rotations of 15° and 30° and each names feature 1, at 0°, as its only neighbor. The test asserts each angle and average against those literals.

**Legacy comparison artifacts.** Run against DREAM.3D v6.5.171 on 2026-09-17: 0 of 5 complete output cases match at `rtol=1e-6, atol=1e-6`. All five have numerical differences; the middle-mismatch and mixed-phase Small IN100 cases also expose D1. A local proof version matches all 5 cases within that tolerance, with paired NaNs. The first three proof comparisons have exact numeric equality.

The three ordinary analytical fixtures compare angles and means within `1e-3°`. The invariant fixture compares the mean within `1e-4°` and checks finite angles from 0° through 62.8°. All pass in CI at `419f9db35`.

**Test sensitivity verification.** Moving divisor initialization inside the neighbor loop changes the middle-mismatch result from 7.5° to 5°. The mismatch-last control remains 7.5° for its one excluded neighbor. The separate invariant fixture uses a mismatch-first order and verifies the mean relation with 7.5° and 12° input rotations.
