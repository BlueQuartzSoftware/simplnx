## How it was generated

Both files predate this V&V pass and their generating pipelines are not recorded in the
repository. What can be established from the naming policy and the file contents:

- `6_6_align_sections_misorientation.dream3d` carries the `6_6_` prefix, which by project
  archive-naming policy means it was produced by **legacy DREAM3D 6.6**, not by SIMPLNX. It
  holds the post-alignment Small IN100 cell arrays.
- `output_align_sections_misorientation.dream3d` has no legacy prefix and contains an
  `Alignment Shifts Data` attribute matrix with the three int64/uint32 shift arrays. That
  output shape did not exist in any legacy DREAM3D version — it was introduced by simplnx
  PR #1237 — so this file can only have been captured from **SIMPLNX's own output**.

## Canonical oracle output

| DataPath | Source of expected values |
|---|---|

| `/DataStructure/DataContainer/Alignment Shifts Data/*` (in `output_...dream3d`) | Previously: SIMPLNX's own output. **Circular — retired as an oracle by this V&V pass.** |

The filter's actual oracle is **Class 1 (Analytical)** and lives entirely in the test source
(`namespace AnalyticalFixtures` in `test/AlignSectionsMisorientationTest.cpp`), not in any
archive. Classes 1 and 4 need no provenance block: the derivations are comments beside the
assertions, and the long-form derivation is reproduced in the V&V report.

## Retired consumer

Before this V&V pass, a second TEST_CASE ("output test") compared the filter's three shift
arrays against `output_align_sections_misorientation.dream3d`. Because that file was captured
from this filter's own output, the comparison could only ever confirm whatever the filter did
on the day of capture — the textbook circular oracle. **That TEST_CASE was retired** and
replaced by hand-derived Class 1 assertions on the same three arrays (see the V&V report's
Test inventory).

The archive is still downloaded because the `6_6_` legacy-parity exemplar in it is still
consumed. `output_align_sections_misorientation.dream3d` now sits unused inside the archive;
it is left in place rather than re-cutting the 357 MB archive to remove one file.

## Also retired: align_sections.tar.gz

A second archive, `align_sections.tar.gz`, was downloaded by
`test/CMakeLists.txt` and referenced by a `TestFileSentinel` in this filter's test expecting a
top-level `align_sections_misorientation.txt` — a **legacy shift text file**. No test read its
contents: the file-comparison assertions were dropped when PR #1237 replaced the text-file
output with DataArrays, leaving only the download and the sentinel. A repository-wide grep
confirmed the CMake line and the sentinel declaration were its only two references, and that
`AlignSectionsMutualInformationTest.cpp` does **not** share it (it uses
`align_sections_mutual_information.tar.gz`). **Both the download and the sentinel were removed
by this V&V pass.** The archive remains in the Data_Archive release; nothing in the repository
references it.
