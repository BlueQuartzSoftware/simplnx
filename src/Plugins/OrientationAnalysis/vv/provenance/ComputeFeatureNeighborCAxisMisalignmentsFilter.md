## How it was generated

PR #1467 added a regression test that reads `compute_feature_neighbor_caxis_misalignments/7_5_simplnx_test_file_25x50_Hex.dream3d`. That test compared its computed neighbor list and average array with the stored arrays named `CAxisMisalignmentList (7_5)` and `AvgCAxisMisalignments (7_5)`. PR #1631 (`ec22ac375`) replaced the archive consumer with synthetic fixtures constructed in `src/Plugins/OrientationAnalysis/test/ComputeFeatureNeighborCAxisMisalignmentsTest.cpp`. These fixtures use literal orientations, phase assignments, neighbor lists, and expected values.

The inline fixture builders are `AnalyticalFixtures::CreateScaffold`, `QuatFromPhiDeg`, `SetAvgQuat`, `BuildArgs`, and `BuildRealisticMicrostructure`. `CreateScaffold` creates an image geometry, cell arrays, feature arrays, and an ensemble array. The algorithm reads feature and ensemble inputs; it does not read the cell geometry or cell-level feature map.

| Group | Arrays | Initial values |
|---|---|---|
| `/ImageGeometry/CellData` | `FeatureIds`, `Phases` | One; the mixed fixture replaces them with its feature map. |
| `/ImageGeometry/CellFeatureData` | `FeaturePhases`, `AvgQuats`, `NeighborList` | Phase zero, identity quaternion, and empty list. |
| `/ImageGeometry/CellEnsembleData` | `CrystalStructures` | Tuple zero is sentinel 999; each fixture assigns its real ensembles. |

The feature-level inputs break feature and phase symmetry through different tilts, neighbor counts, and crystal structures. The cell layout is a visualization aid. Its equal X and Y dimensions and zero origin do not enter this algorithm.

**Simple Hex Pair**

The scaffold has a 1×1×1 image and three feature tuples, including background. Features 1 and 2 have Hexagonal_High structure, tilts 0° and 10°, and reciprocal neighbor entries. Both pair angles and both averages must be 10°.

**Realistic Microstructure**

The scaffold has a 10×10×1 image and seven feature tuples, including background. Features F1, F2, F4, F5, and F6 use phase 1, whose structure is Hexagonal_High. F3 uses phase 2, whose structure is Cubic_High.

| Feature | Tilt | Neighbor list |
|---|---|---|
| F1 | 0° | F2, F4 |
| F2 | 5° | F1, F3, F4, F5 |
| F3 | 10° | F2, F5, F6 |
| F4 | 15° | F1, F2, F5 |
| F5 | 20° | F2, F3, F4, F6 |
| F6 | 25° | F3, F5 |

The cell layout that defines these face adjacencies is:

```text
y = 0..3: x = 0..2 -> F1 | x = 3..6 -> F2 | x = 7..9 -> F3
y = 4..9: x = 0..3 -> F4 | x = 4..7 -> F5 | x = 8..9 -> F6
```

F2/F4 and F3/F5 each share one cell face across the y=3/y=4 boundary. They are face adjacencies, not diagonal-only contacts. The algorithm consumes the supplied neighbor lists and does not derive them from the cell map.

**Mismatch Last Order**

The scaffold has a 1×1×1 image and five feature tuples. F1, F2, and F3 have Hexagonal_High structure and tilts 0°, 5°, and 10°. F4 has Cubic_High structure. F1's neighbor list is [F2, F3, F4], so its output is [5°, 10°, NaN] and its average is 7.5°. The old divisor also gives 7.5° for this ordering; this is a control case.

**Class 4 invariants**

The invariant test reuses the realistic fixture. Its three sections check the finite-angle range [0°, 90°], the average of the non-NaN list entries, and NaN outputs for the cubic focal feature F3. The mean invariant detects the divisor defect independently of the chosen tilt values.

**Quaternion boundary fixture**

The hidden `genuine HDF5 1MiB-chunk tail oracle` constructs 65,537 feature quaternions. It asserts a 65,536-tuple chunk shape and assigns tilts 15° and 30° to the last tuple of the full chunk and the first tuple of the tail. Both features point to identity feature 1. The expected pair angles and averages are 15° and 30°. This fixture uses a `DataGroup` with the same feature and ensemble paths; no image geometry is needed.

**Validation fixtures**

The tuple-count fixture supplies eight neighbor and quaternion tuples but seven phase tuples, so preflight must return `-1560`. The phase-index fixture uses values -1 and 2 with two ensemble tuples. It expects `-1564` for either a focal or neighbor lookup and permits an invalid phase on unused background feature zero.

## Canonical oracle output

The canonical values are defined in the C++ test source. The registered archive is not the correctness oracle.

| DataPath | Source of expected values |
|---|---|
| `/ImageGeometry/CellFeatureData/CAxisMisalignmentList` | Class 1: folded absolute tilt differences for equal accepted hexagonal structures; NaN for excluded pairs. |
| `/ImageGeometry/CellFeatureData/AvgCAxisMisalignments` | Class 1 arithmetic means and Class 4 checks of the mean of non-NaN entries. No accepted entries gives NaN. |

For a pure x-axis rotation by Φ, the quaternion is `(sin(Φ/2), 0, 0, cos(Φ/2))`. Applying the transposed orientation matrix to crystal [001] tilts the c-axis by Φ. Two such axes have dot product `cos(Φ_A - Φ_B)`. Their unoriented-axis angle is the absolute tilt difference folded into [0°, 90°]. This gives the expectations without calling the production orientation-matrix code.

The realistic fixture gives:

| Feature | Pair angles | Accepted count | Sum | Expected average |
|---|---|---|---|---|
| F1 | [5°, 15°] | 2 | 20° | 10° |
| F2 | [5°, NaN, 10°, 15°] | 3 | 30° | 10° |
| F3 | [NaN, NaN, NaN] | 0 | 0° | NaN |
| F4 | [15°, 10°, 5°] | 3 | 30° | 10° |
| F5 | [15°, NaN, 5°, 5°] | 3 | 25° | 25/3° |
| F6 | [NaN, 5°] | 1 | 5° | 5° |

The test checks all 18 list entries and six averages. Finite values use an absolute tolerance of 0.001°; NaN values use `std::isnan`. F2, F5, and F6 expose the lost divisor decrements. F3 distinguishes a zero average from the required NaN when all three neighbors are excluded.

No fixture tests an angle above 90° or selects Hexagonal_Low. The range invariant does not exercise the folding branch. The report lists these coverage gaps separately.

## Regenerated to fix a circular-oracle situation?

No replacement archive was generated. PR #1631 removed the archive comparison test and added independent Class 1 and Class 4 fixtures. The registered archive name and SHA512 remain unchanged from PR #1467.

The old consumer used stored expected arrays from a hexagonal dataset. That coverage could not expose exclusions in a mixed-structure list. This is a coverage limitation, not proof that the archive had a circular generation process. The current fixtures include the excluded neighbors needed to detect D1.
