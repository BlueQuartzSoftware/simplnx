## How it was generated

The removed archive test identifies SIMPL/DREAM.3D as the producer of `so3_cubic_high_ipf_001.dream3d`. The file contains 343,963 cubic-phase cells and an embedded legacy RGB array. The comparison pipelines read its Euler Angles, Phases and Crystal Structures, then compute TSL colors for reference direction [0,0,1] with masking disabled. The current test builder `BuildAnalyticalDataset()` instead constructs six cells with explicit Euler angles, phases and boolean/uint8 masks in C++.

The inline fixture has Crystal Structures `[Unknown, Cubic_High, Hexagonal_High]` and Phases `[1,1,2,1,0,2]`. Its Euler triples are `(0,0,0)`, `(0.3,0.4,0.5)`, `(0.1,0.2,0.3)`, `(0.3,0.4,0.5)`, `(0.3,0.4,0.5)` and `(0.7,0.8,0.9)` radians. Cell 3 is masked; cell 4 has the unknown structure. The filter does not use geometry coordinates, so origin and spatial-axis asymmetry do not affect this oracle.

The comparison artifacts are `vv_work:ComputeIPFColorsFilter/pipelines/ipf_6_5_171.json`, `vv_work:ComputeIPFColorsFilter/pipelines/ipf_nx.d3dpipeline`, and the refreshed release pipelines generated by `vv_work:ComputeIPFColorsFilter/scripts/build_release_matrix.py`. The comparison reads integer RGB arrays and counts tuple/component differences in `vv_work:ComputeIPFColorsFilter/scripts/compare_release_matrix.py`.

## Oracle provenance (Classes 2, 3, 5 only)

The Class 2 reference is `EbsdLibReferenceColor()` in `src/Plugins/OrientationAnalysis/test/ComputeIPFColorsTest.cpp`. It calls the linked C++ EbsdLib directly with the fixture Euler angles, crystal structure, normalized direction and color key. `vcpkg.json` requires EbsdLib 3.1.2 or later. Inputs are deterministic; no random seed or external oracle script is used. This reference checks SIMPLNX routing and RGB packing, not the color mathematics shared with EbsdLib.

The test name retains `Class 1/2/3 Oracle`, but its red-corner assertion uses a literal expectation without a paper citation. The report classifies that assertion as analytical.

Run against DREAM.3D v6.5.171 on 2026-07-09: 343,949 of 343,963 RGB tuples match exactly; all match within one channel level. SIMPLNX matches the embedded legacy array exactly. `vv_work:ComputeIPFColorsFilter/README.md` identifies the stock PipelineRunner; `vv_work:ComputeIPFColorsFilter/results/three_way_comparison.txt` records the results.

Run against DREAM.3D v6.5.171 on 2026-09-17: 343,949 of 343,963 RGB tuples match exactly for each of DREAM3D-NX v7.4.1 and v7.4.2; all match within one channel level. Both releases match each other and the embedded legacy colors exactly. Results are in `vv_work:ComputeIPFColorsFilter/results/release_matrix/comparison.md` and `vv_work:ComputeIPFColorsFilter/results/release_matrix/comparison.json`. The legacy runner log reports SIMPLib 1.2.828 in `vv_work:ComputeIPFColorsFilter/results/release_matrix/logs/legacy_6_5_171.stdout.txt`.

The current algorithm changed after that comparison: `4ec21e93f`, 2026-09-20, PR #1568, introduced Direct/Scanline execution and negative-phase validation. The release comparison does not establish current-algorithm parity. The earlier 2026-07-09 run also predates `ce6b67b5f`, 2026-07-13, PR #1666.

Release-source inspection used `git show` on all ten `upstream/release/v<version>` refs from v7.0.0 through v7.4.2. Paths below are relative to `src/Plugins/OrientationAnalysis/src/OrientationAnalysis/Filters/Algorithms/`.

| Defect | Release-source evidence | Correction |
|---|---|---|
| D2: counter race | `ComputeIPFColors.hpp` declares plain `int32_t m_PhaseWarningCount` in v7.0.0 through v7.4.1 and `std::atomic_int32_t` in v7.4.2; the worker increments it in `ComputeIPFColors.cpp`. | PR #1666 (`ce6b67b5f`) changes the counter to atomic. Current Direct retains that type; Scanline uses a serial local counter. |
| D3: negative phase | `ComputeIPFColors.cpp` in all ten releases checks only the upper phase bound before Crystal Structures access. | PR #1568 (`4ec21e93f`) adds `-48001` in Direct and Scanline. |

DREAM.3D tag `v6.5.171`, `Source/Plugins/OrientationAnalysis/OrientationAnalysisFilters/GenerateIPFColors.cpp`, has both defects: its worker reads Crystal Structures with no lower phase bound and increments a shared counter from `tbb::parallel_for`. `GenerateIPFColors.h` declares that counter as plain `int32_t`.
