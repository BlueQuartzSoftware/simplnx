### Algorithm summary

For each voxel `i` with `cellPhase[i] > 0` AND phase is `Hexagonal_High` or `Hexagonal_Low`:
1. Take voxel quaternion → orientation matrix → transpose → multiply by `c_crystal = [0,0,1]` to get the voxel's lab-frame c-axis
2. Take the feature's pre-computed `AvgCAxes[featureId]` (typically from `ComputeAvgCAxesFilter`)
3. `dot = voxel_caxis · feature_avg_caxis`
4. `w = acos(clamp(dot, -1, 1)) * 180/π` (in degrees)
5. `if (w > 90.0) w = 180.0 - w;` — **antipodal fold** for hex c-axis equivalence
6. Write `cellRefCAxisMis[i] = w`; skipped voxels (non-hex, featureId==0, cellPhase==0) get `0.0f`

Per-feature aggregations (in degrees):
- `featAvgCAxisMis[fId]` = arithmetic mean of `cellRefCAxisMis[i]` over hex-cells with `featureIds[i] == fId`, divisor `counts[fId]`
- `featStdevCAxisMis[fId]` = **population** standard deviation (divisor `counts[fId]`, not `counts[fId]-1`); accumulator is **double** post-PR-#1438

**Restrictions**: Only `Hexagonal_High` and `Hexagonal_Low` Laue groups supported. Other Laue groups trigger warning `-9803`. No hex phase at all → error `-9802`.

**Threading**: Single-threaded; cancel checks in 4 loops (PR #1582). No `ParallelDataAlgorithm`.

**Mode note (brief correction)**: this filter **only supports the feature-average c-axis mode** — it consumes a pre-computed `AvgCAxes` feature-data array. There is no "arbitrary reference voxel" code path here; that capability — if it exists at all — would belong to a sibling filter (e.g., `ComputeFeatureReferenceMisorientationsFilter`).

**Math form note (brief correction)**: the algorithm computes `acos(clamp(dot, -1, 1))` followed by `if w > 90° then w = 180 − w`, not the mathematically equivalent `acos(|dot|)`. The two are numerically distinct near the 90° boundary (~1 ULP); the algorithm uses the fold form unconditionally with no parameter to switch.

### Recommended starting point

**Class 4 (Invariant) primary** — 8 testable invariants flow directly from the algorithm:

1. **Range**: every `cellRefCAxisMis[i] ∈ [0°, 90°]` (the fold guarantees this; `std::clamp(dot, -1, 1)` before `acos` also rules out NaN)
2. **Non-negativity**: every output `≥ 0`
3. **Skip semantics**: for any cell with `cellFeatureId == 0` OR `cellPhase == 0` OR non-hex phase → `cellRefCAxisMis[i] == 0.0f` exactly (post-condition assertion)
4. **Per-feature mean**: `featAvgCAxisMis[fId] == arithmetic mean of cellRefCAxisMis[i] over hex cells with featureIds[i] == fId`
5. **Per-feature stdev**: `featStdevCAxisMis[fId] == population stdev (÷counts[fId], not counts[fId]-1)`
6. **Identity case**: a feature whose hex voxels all have orientation matching `AvgCAxes` produces per-voxel `0.0` and feature average/stdev `0.0`
7. **Antipodal symmetry**: output is invariant under sign-flip of feature `AvgCAxes` row (hex c-axis equivalence — the load-bearing physics assumption)
8. **Units**: all outputs are in degrees (algorithm multiplies by `Constants::k_180OverPiD`)

**Class 1 (Analytical) supplemental** — hand-derivable spot check:
- Single feature, single cell, quaternion = identity `{1,0,0,0}`, `AvgCAxes = {0,0,1}` → `cellRefCAxisMis[0] == 0.0` exactly. (Identity matrix · identity vector = identity vector; dot product with itself = 1; `acos(1) = 0`.)

**Class 3 (Paper-based)** — *not* recommended unless a citation for hex-c-axis-misalignment-distribution analysis is found in algorithm headers or legacy DREAM3D docs. Audit found none.

> **Symptom:** SIMPLNX `featStdevCAxisMis` differs from SIMPL ≤ 6.5.172 output by amounts up to ~0.0001 (per the user-facing doc); larger deviations may appear on ARM platforms.
> **Root cause:** Legacy DREAM3D ≤ 6.5.172 accumulated squared deviations for population stdev in `float32`. SIMPLNX (post-PR-#1438) accumulates in `double` and only narrows when writing the final `float32` array. StdDev is a sum-of-squares whose dynamic range is order-of-magnitude wider than inputs — single-precision accumulation accrues catastrophic cancellation on large feature-cell counts.
> **Affected users:** Anyone comparing exact stdev values against legacy outputs; users on ARM where the legacy single-precision rounding mode differs.
> **Recommendation:** **Trust SIMPLNX.** Legacy was less accurate. A back-port to legacy DREAM3D is mechanically simple (change one accumulator type) but probably not worth the effort.

#### D2 — 90°-boundary fold (Low, verify only)

> **Deviation ID:** `ComputeFeatureReferenceCAxisMisorientations-D2`
> **Symptom:** *(if observed)* per-voxel angles in the open neighborhood of `w = 90°` differ between SIMPLNX and legacy by ~1 ULP.
> **Root cause:** Both versions compute `acos(clamp(dot, -1, 1))` followed by `if w > 90° then w = 180 − w`. The fold is sensitive to whether `dot` was rounded just above or below the value producing `acos = 90°`. The mathematically equivalent `acos(|dot|)` form would avoid the fold but is not what either version uses.
> **Recommendation:** Document as expected; withdraw the deviation if Phase 9 reveals no 90°-boundary deltas.

#### D3 — EbsdLib 2.0.0 math swap (Low, verify only)

> **Deviation ID:** `ComputeFeatureReferenceCAxisMisorientations-D3`
> **Symptom:** *(if observed)* per-voxel angles shift by ULP-level amounts at the PR #1472 commit boundary.
> **Root cause:** PR #1472 replaced `OrientationTransformation::qu2om<QuatD,OrientationD>` + `OrientationMatrixToGMatrixTranspose` + left-multiply with `ebsdlib::QuaternionDType.toOrientationMatrix()` + `oMatrix.transpose() * cAxis`. The two are mathematically equivalent but reorder floating-point operations.
> **Recommendation:** Re-run `caxis_data.tar.gz` exemplar at the PR #1472 boundary; record any delta. If below `UnitTest::EPSILON`, no action; otherwise document here. Withdraw the deviation if no measurable difference is observed.
