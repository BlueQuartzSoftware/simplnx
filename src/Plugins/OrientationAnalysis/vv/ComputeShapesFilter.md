## Summary

`ComputeShapesFilter` accumulates the second-order moments of every **Feature** in an `ImageGeometry` and reduces them to best-fit-ellipsoid semi-axis lengths, aspect ratios, principal-axis Euler angles, the moment invariant Omega3, and each **Feature**'s volume. Verification is **oracle-first and analytical**: a closed form for the algorithm's own eight-point octant quadrature over an axis-aligned box of voxels was derived by hand from the source, cross-checked against an independent numpy re-implementation, and validated against SIMPL 6.5.171's own published test numbers before any comparison run. Four defects were found and fixed — two of them shared with DREAM3D 6.5.171 — and one shared latent issue is documented rather than changed. All 5 test cases pass with 2613 assertions.

## Bug Fixes (this pass)

### ComputeShapesFilter-D1 / -D2: the 2D path sampled voxel corners and assumed the in-plane axes were X and Y — fixed

Both are shared with DREAM3D 6.5.171 and both have full deviation entries. Summary: `findMoments2D` sampled `xPoint * modXRes + origin[0] * scale`, the voxel corner, while the `Centroids` it measures offsets against come from `ComputeFeatureCentroids`, which averages voxel *centers*; and it read `spacing[0]`/`spacing[1]`, `origin[0]`/`origin[1]`, `Centroids` components 0 and 1, and `konst2 = spacing[0] * spacing[1]` regardless of which axis was flat. `findAxes2D` repeated the axis assumption in its degenerate-moment fallback. Both routines now derive two in-plane axis indices the same way `findMoments2D` chooses `xPoints`/`yPoints`, and sample the voxel center.

### NX-only regression: the 2D degenerate axis Euler angle was `pi/180`, not `pi/2`

`findAxisEulers2D` writes a single in-plane angle when the off-diagonal moment `Ixy` is exactly zero: `pi/2` when the long axis is the local Y axis, `0` when it is the local X axis. SIMPLNX wrote `nx::core::numbers::pi / 180.0F` — a 90x mis-transcription of legacy's `k_PiOver2`, and dimensionally a degree-to-radian conversion factor rather than an angle. Fixed to `nx::core::numbers::pi / 2.0`. Not recorded as a deviation because legacy is correct here; the NX port introduced it.

**This defect was masked by `-D1`.** The corner-sampling bias makes `sum_voxels X*Y = N * (mod_x/2) * (mod_y/2)`, which is strictly non-zero for every non-empty 2D feature, so `Ixy == 0` was unreachable and the mis-transcribed line never executed. The bug only becomes observable once `-D1` is fixed. Evidence class: **analytically derived, then executed** — fixture F5's stock output was `1.5086188` from the general branch, exactly the value predicted for a non-zero `Ixy`, while fixture F6b (whose stock `Ixy` happens to cancel to `-0.0`) did emit `0.01745` = `pi/180`.

### Empty-feature axis outputs were NaN

For a feature id that no cell references, the moment matrix is identically zero, so `findAxes` computes `a = pow((A*A*A*A)/(B*C), 0.1)` with `A == B == C == 0` — a `0/0` NaN that propagates into all three `AxisLengths` components. `findAxisEulers` then reports the arbitrary eigenvector basis of the zero matrix as a real orientation (observed: `(pi, pi/2, pi/2)`). In the 2D path the `r2 <= 0` fallback wrote `spacing_2/spacing_1` as an aspect ratio (observed: `1.0`). `findAxes` (:506), `findAxes2D` (:597) and `findAxisEulers` (:664) now detect `volumes[featureId] == 0.0f` explicitly and write zeros. `findAxisEulers2D` carries no such guard; for an empty feature its moments are all zero, so `Ixx == Iyy == Ixy == 0` and the routine falls into its existing degenerate branch (`Ixy == 0 && Iyy >= Ixx`), which already writes zero — see coverage row 21 and fixture F5 feature 2. This is consistent with the zero-initialized state of the output arrays. Requester decision, 2026-08-20. Not a deviation entry — legacy has the same hole, but this is a strict improvement rather than a behavioral difference users would migrate across, and it is called out in the user documentation.

## Oracle

*Class:* **1 (Analytical)** for F1–F6 and F8, **2 (Reference implementation)** for F7, **4 (Invariant)** across all nine.

### The closed form

Derived by hand from `Algorithms/ComputeShapes.cpp`, for a **Feature** that is an axis-aligned box of `N_x x N_y x N_z` voxels of spacing `d` with the centroid at the box center:

- The eight-point octant quadrature contributes, per voxel and per axis, `8*X^2 + D_i^2/2` where `X` is the offset of the voxel center from the centroid and `D_i = d_i * m_ScaleFactor`. Summing over the box and applying `konst1 = D_x*D_y*D_z/8` gives `P_i = V_mod * D_i^2 * G_i` with `G_i = (N_i^2 - 1)/12 + 1/16` and `V_mod = N_tot * D_x*D_y*D_z` — which is exactly the `vol5` the code carries into Omega3.
- The `1/16` is the implementation's quadrature self-moment. The exact volume integral would give `1/12`. This is the deliberate discriminator: an oracle that used the exact integral would still be within a fraction of a percent on large features and completely wrong on a single voxel.
- Cross moments vanish, so `Ixx = P_y + P_z`, `Iyy = P_x + P_z`, `Izz = P_x + P_y` and the moment matrix is diagonal.
- `Q_i = 15 P_i/(4 pi)`. The three inertia eigenvalues are `{Q_y+Q_z, Q_x+Q_z, Q_x+Q_y}` scaled; after `TripletSort` descending, `findAxes`'s `A`, `B`, `C` collapse algebraically to the three `Q_i` sorted **descending**. With `m = (Q_x Q_y Q_z)^(1/5)`, `a = sqrt(Q_max/m)`, `b = sqrt(Q_mid/m)`, `c = sqrt(Q_min/m)`, all divided by `m_ScaleFactor`. `a*b*c == m`.
- `u200`, `u020`, `u002` collapse to `P_x`, `P_y`, `P_z` and the cross terms to zero, so `Omega3 = V_mod^5 / (P_x P_y P_z * 2000 pi^2/9)`, which reduces to the scale-free and spacing-free `Omega3 = 9 N_tot^2 / (2000 pi^2 G_x G_y G_z)`.
- 2D: `Ixx = A_mod * E_1^2 * G(n_1)`, `Iyy = A_mod * E_0^2 * G(n_0)`, `Ixy = 0`; `a = (4/pi)^(1/4) (r1^3/r2)^(1/8)`, `b = (4/pi)^(1/4) (r2^3/r1)^(1/8)`, `b/a = sqrt(r2/r1)`, `c = 0`, `Omega3 = 0`.

### Provenance of the closed form, in the order the work was done

1. Read all four sources (SIMPLNX filter and algorithm, legacy `FindShapes.cpp`, legacy `FindShapesTest.cpp`) plus both centroid filters and `EbsdLib/Orientation/OrientationMatrix.hpp`.
2. Derived the closed form above **by hand** from the SIMPLNX algorithm source.
3. Wrote an independent brute-force numpy re-implementation of the same loops (`ww_work/ComputeShapes/oracle.py`, `moments_numeric_3d` / `moments_numeric_2d`) that works for arbitrary voxel sets, and cross-checked it against the analytic moments for twelve 3D and eight 2D geometry/convention combinations. The two derivations agree to `1e-11` relative on all six moment components.
4. **Validated both against SIMPL 6.5.171's own published test numbers.** `FindShapesTest.cpp` asserts fifteen values for a 256x128x64 box of spacing `(0.75, 0.5, 0.25)` and a 128x256x1 slab of spacing `(0.75, 0.5, 1.0)`. Evaluating the closed form with the *legacy* voxel-corner convention reproduces all fifteen, including `Omega3 = 0.7871799` against the asserted `0.78715 +/- 0.0001` and the 2D `AspectRatios[0] = 0.7500472` against the asserted `0.75 +/- 0.0001`. This is what makes the closed form trustworthy independently of SIMPLNX.
5. Computed the expected values for the nine fixtures and compiled them into the test.
6. Built and ran. RED/GREEN below.
7. **Then** wrote `predict_legacy.py` from the legacy source and generated `predictions.txt`, and **then** ran the legacy binary.

`6_6_stats_test_v2.tar.gz`, SHA512 `e84999dec914d81efce4fc4237c49c9bf32e48381b1e79f58aa4df934f0d7606cd7a948f9a5e7b17a126a7944cc531b531cfdc70756ca3e2207b20734e089723`, matching `src/Plugins/OrientationAnalysis/test/CMakeLists.txt:130`. **Not regenerated and not renumbered by this pass**, and its `download_test_data()` line is byte-unchanged.

The archive's `Omega3s`/`AxisLengths`/`AxisEulerAngles`/`AspectRatios`/`Shape Volumes` were generated by a legacy `FindShapes` — the archive's embedded pipeline records `FilterVersion 6.6.373` for step 31 — on an 80x80x117 Small IN100 crop of isotropic spacing 0.25 with 620 features. They are therefore genuine legacy output, but from a build **later than the 6.5.171 baseline**, which turns out to matter a great deal.

**The archive was compared full-array, not through the unit test.** `UnitTest::CompareDataArrays` breaks out of its loop at the first index where two values differ *at all*, and only sets `failed` when that first difference exceeds `EPSILON = 1e-4` absolute — so the elements after the first difference are never examined. Running `ComputeShapesFilter` on the archive's own geometry and `Centroids` and diffing every element with `h5py` (`ww_work/ComputeShapes/results_archive_check.txt`) gives:

| Array | Elements exactly equal | max abs diff | max rel diff |
|---|---|---|---|
| `Omega3s` | 620 / 620 | 0 | 0 |
| `AxisLengths` | 1860 / 1860 | 0 | 0 |
| `AspectRatios` | 1240 / 1240 | 0 | 0 |
| `Shape Volumes` | 620 / 620 | 0 | 0 |
| `AxisEulerAngles` | 1626 / 1860 | 4.8e-7 | 3.5e-7 |

Four of the five arrays are **bit-identical across all 620 features**, and the fifth differs only at the float32 noise floor of the eigen-to-Euler chain. Two conclusions follow. First, the archive is a genuine Class 2 oracle rather than a circular one: an independent legacy implementation reproduces SIMPLNX exactly on real data. Second — and this is the load-bearing part — the 6.6.373 `FindShapes` that generated it must sample voxel **centers**, because the corner convention differs from the center convention by 5% to 50% relative on features this size. That is a third independent confirmation of `-D3`: 6.5.171 is the outlier, and the later legacy line and SIMPLNX agree. Evidence class: **executed** (the 6.6.373 source was not available for inspection; the conclusion is drawn from bit-exact agreement over 620 features).

The archive comparison is retained as a production-scale regression net, and the fact that it still passes unchanged is the positive evidence that this pass's four fixes are confined to the 2D path and to empty features. The archive contains exactly one feature with zero volume — id 0, which every version of the algorithm skips — so it cannot exercise the empty-feature path either.

A provenance sidecar is added at `src/Plugins/OrientationAnalysis/vv/provenance/6_6_stats_test_v2.md` recording the embedded pipeline, the version caveat and the full-array comparison above.

## Deviations from DREAM3D 6.5.171

Comparison run on all nine fixtures. Four deviations, each with a full entry in `src/Plugins/OrientationAnalysis/vv/deviations/ComputeShapesFilter.md`:

- `ComputeShapesFilter-D1` — 2D voxel-corner sampling. Shared bug, fixed in SIMPLNX this pass.
- `ComputeShapesFilter-D2` — 2D in-plane axis mapping. Shared bug, fixed in SIMPLNX this pass. Also the only cause of a `Volumes` divergence.
- `ComputeShapesFilter-D3` — 3D voxel-corner sampling. Legacy-only, and specific to the 6.5.x line: the legacy 6.6.373 build that generated the exemplar archive agrees with SIMPLNX bit-exactly. Recommendation: trust SIMPLNX.
- `ComputeShapesFilter-D4` — the handedness correction is dead code in both codebases. Shared latent; documented, deliberately **not** changed because any change alters reported values.

Observed matched predicted in every cell of the element-wise columns, digit for digit. Two cells warrant naming because they are *agreements* the coarse prediction table did not call out, both of which the per-fixture predictions did:

- **F6b `AxisEulers` exact.** Stock legacy's `Ixy` for this X-flat slab cancels to `-0.0` by coincidence — the wrong `Centroids` component it reads happens to fall on the local-x index midpoint — so it takes the degenerate branch and writes `k_PiOver2`, which equals the correct post-fix value. This is also the one fixture where a *stock* run exercises the `pi/180` line, and it is how that line was caught with executed evidence rather than by source reading alone.
- **F7 `AxisEulers` aligned.** The corner-sampling bias is symmetric in x and y for this diagonal plate, so it does not tilt the 45-degree short axis; `|dot|` is 1.0. The long-axis direction *does* tilt (`|dot| = 0.996`), but that row is not recoverable from the Euler angles and is not asserted.

The two empty features (F2 feature 3, F5 feature 2) are excluded from the alignment verdict and reported separately: legacy emits `AxisLengths = (nan, nan, nan)` and `AxisEulerAngles = (pi, pi/2, pi/2)` for F2 feature 3, and `AspectRatios = (1, 0)` for F5 feature 2, where SIMPLNX now emits zeros. Intentional divergence.

### Root cause proven by patched legacy

A surgical patch to a local build of the legacy `FindShapes` source — voxel-center sampling in both the 3D and 2D paths, plus the 2D in-plane axis remap, and nothing else — makes the legacy build reproduce this filter's output on all nine fixtures: **bit-exact** on `Centroids`, `Volumes`, `Omega3s`, `AxisLengths` and `AspectRatios` for seven of nine, with residuals on only two: F1 (`4.2e-7` on `Omega3s`, `3.1e-6` on `AxisLengths`, `3.9e-6` on `AspectRatios` — `m_ScaleFactor = 1/0.75` is not exactly representable) and F7 (`2.3e-7` on `Omega3s` alone — the only fixture with non-zero cross moments, so the `float32` determinant expression cancels); and exact on the 2D `AxisEulerAngles` for all three 2D fixtures. This confirms that the entire observed divergence is accounted for by `-D1`, `-D2` and `-D3` and by nothing else. The patched build is internal proof tooling and is not a shipping comparison target.
